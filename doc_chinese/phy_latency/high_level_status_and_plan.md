## 0.1 ★★★ 设计目标与原则（**2026-09-26 用户裁定：G1/G2 是根本，其余都可改变**）

> 这一节**优先于下面的 V1–V5**：V1–V5 是**代理量与验收读数**，G1/G2 是**目标本身**。
> 来源：开发文档 §6.89–§6.92（用户三轮裁定的原文精神）。

### G1 —— 数据流全程在 GPU（**不可交易**）

**从 IQ 到 LLR（最终到 MAC PDU）一步到底，不落地、不中转**：

* 样点**零拷贝**：GPU 直接读接收缓冲（`zero-copy wraps`、`wrap_copies=0`）；
* **宿主不搬数据**：`host sample assembly: 0 copied`、`crossings 0.00+0.00 / 跳`、`ce device estimates … host=0`；
* 网格、信道估计、均衡、解映射**都在设备上**（D1 交棒让它们落在同一条提交里）。

### G2 —— 宿主一次性参与（**不可交易**）

**在跳入口把该跳的全部提交"背靠背"做完，然后全程靠边站，直到出口取结果**：

* **无中途等待**：不得重现历史上的 `wait_slot`（阻塞 `waitUntilCompleted`）与 `gpu_wait`；
* **无中途回合**：宿主不得为了编码下一条缓冲而**读回设备上的值**（历史上的 CFO 读回就是反例）；
* 出口之前，宿主在 PHY pipeline 里**不做别的事**。

**✅ 已量化（2026-09-26，腿 `p53-n78-tailmark`，开发文档 §6.97）**：一跳的宿主参与 **中位 94.0 µs**
（**头 47.2**：入口→抽取提交；**尾 46.8**：抽取提交→lane 提交），覆盖 **145291/145291 lane**、`0` 条"总额短于头"；
同一腿里 `residency` 569.0 / `gap` **10.7** / `[ul_dft_wait]` 无样本 / `gpu_wait` **0.0**
⇒ **宿主只占一跳窗口的 16.5%，而且全程没有等设备** —— "入口背靠背做完、然后靠边站"从定性判据变成了一个可验收的数字。

### ★ 蕴含的设计原则：**让 GPU 内部那条"不断流"的处理链越来越长**

> 用户原话精神：**"让在 GPU 内部不断流的数据处理链条越来越长（例如把 LDPC 也搬入 GPU Metal），让 CPU 越来越少的参与 PHY pipeline，最终从 IQ 到 MAC PDU 完全靠边站。"**

| 层级 | 现状（2026-09-26）| 下一步（蕴含的方向）|
|---|---|---|
| 设备内链 | IQ（零拷贝）→ 前端 DFT → 信道估计 → 均衡 → 解映射 → **LLR** | **把 LDPC 解码搬进 Metal**（`dec_type=metal` 已存在：`ldpc_decoder_metal` + `ocudu_metal_decoder_engine`）⇒ **LLR 不再落地** |
| 宿主↔设备交叉 | 两个：**IQ 上行**、**LLR 下行** | 变成**一个且更小**：**译码后的 TB / CRC 判决** |

### 三条推论（写下来，避免以后再走回头路）

1. **`cbs/lane=3.00` 不是"退步"，而是"另一个形状"**：只要宿主在入口背靠背提交完、之后全程靠边站，它与 2.00 同等合规；若它更快，那就是**同时满足 G1+G2 的交付候选**，需要更新的只是 V4 的代理阈值。
2. **任何"把 CPU 叫回来"的方案一律否决**：包括但不限于宿主 staging/拷贝（破 G1）、宿主中途等待或读回（破 G2）——即使它更快。
3. **结构类改动之间可以叠加**：S-E（并发/队列结构）与"把链条搬进 GPU"是**不同维度**，可同时得到收益；因此 S-E 排在**最后**（用户裁定），而不是用来替代当前的链条延长工作。
