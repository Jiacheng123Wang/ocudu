## 0. 一句话结论

**目标达成了两件、第三件被实测关闭：CE 的 kernel 融合从 0 做到 4 项并全部落地验收 ✓；
"那几百 µs 的时间未解之谜"被查清 —— 它不是被零碎 kernel 缠绕掉的，而是设备在等本槽的样点 ✓；
而一旦查清，这个工作流的性能目标就自动失效了（设备余量 4.7×）✗。**

★ 换句话说 ✓：**立项时怀疑的东西（CE kernel 太零碎）确实存在 ✓，但它不是那几百 µs 的原因 ✗；
把它收拾干净是值得的 ✓（4 项融合 ✓、每跳相关派发 4 → 1 ✓），而它换不来时延 ✗。**

## 3. 被证否的（**这一节是本文最有价值的部分** ✓，免得重犯 ✓）

### 3.1 ✗✗ "那几百 µs 是 CE 零碎 kernel 缠绕" —— **数字上不成立**

CE 全部算力 **≈38 µs/跳** ✓，而那几百 µs 差一个数量级 ✓。
★ 撬动它的 `OCUDU_UL_RX_SYMBOLS=1` **已飞过并证否** ✗（前端 **14 CB/符号** ⇒ **+676 µs** ✓、UL 每跳 TB 塌 15× ✓）。

### 3.2 ✗✗ **五个"时间去哪了"的假设，全部证否**（§2.17 等 ✓）

| 假设 | 证否方式 |
|---|---|
| 内核本身贵 ✗ | 微基准：纯算力 ~67 µs ✓，与 463 µs 差一个数量级 ✓ |
| **fence** ✗ | 两条独立证据 ✓：空口消融（`mkf018/019` ✓）+ Q24 逐标签（一跳 fence 总账 **11.6 µs = 2.0 %** ✓）|
| **与并发 lane 争设备** ✗ | `mkf022`：并发 1 时 `busy` 确实降了 ✓，但端到端**更差** ✗（`max_pusch_and_srs_concurrency<=1` 是 **STRAND** ✓ ⇒ 线程停摆 ✓）|
| **dispatch 价 ~39 µs** ✗✗ | `mkf023`：★ **一个边界 ≈6.5 µs** ✓ —— 那条记录**大了一个数量级** ✗ |
| **跨 CB 边界贵** ✗ | `mkf024-split`：加**一整条 CB 边界**（commit + endEncoding + 设备侧切换 ✓）后仍在 **±1 µs** 内 ✓ |

⇒ ★ **能想到的结构全部量过，归因边际收益 = 0** ✓ ⇒ ★ **"那几百 µs"被归到"等样点"** ✓。
★ 附带证否 ✗：**"更细的 GPU 计时"这条路本机不存在** ✗（M4 Pro `atDispatchBoundary = NO` ✓，离线查证 ✓）。

### 3.3 ✗✗ **"精度墙"** —— 引的是**已被驳倒的论据**（§2.20(3ter) ✓）

★ 本工作流（包括我）**两次**引用"融合 `corr+inv+weights` 撞精度墙" ✗（引 `9.7e-1` / `−18.7 dB` ✓）。
★ **真相**（`f2376a1f42` ✓，**比那条注释晚一天** ✓）：K1 曾因**性能**移到宿主 ✓，
后被**不成立的精度理由**留着 ✗ —— ★ 设备求逆的 **W 误差 7.67e-4** vs 宿主 **1.40e-5**
= ★ **≈0.003 dB SINR** ✓，而 **−18.7 dB 是两个 staging 缺陷**（已修 ✓）。
★ **现状** ✓：**矩阵求逆在 GPU 上、而且是默认** ✓（`device_inverts()` ✓、`L=54 ≤ 54` ✓）
⇒ ★ **一跳没有 GPU↔CPU 往返** ✗；门槛 54 是内核 **`MAX_N` 容量** ✓、**不是精度阈值** ✓。

### 3.4 ✗✗ **两对融合的"前置"被实测判定不成立**

| 对 | 为什么融不了 | 出处 |
|---|---|---|
| **`corr_a` + `inv`** ✗✗ | ★ 它的前提是**把 K1 的消元放进 `corr.metal` 的严格文件** ✓，而**实测该模式改变 K1 的输出** ✗：**半数的几何上 26–39 % 的 LLR 变了、`max|Δ|` 12–19**（int8 ✓）、另一半几何逐位不变 ✓ ⇒ ★ **不是"几 ulp"，是一次真正的数值改变** ✗ | §2.24 ✓ |
| **`inv` + `weights`** ✗✗ | ★ **同一次测量的推论** ✓：两者必须同处一个数学模式 ✓ ⇒ K1 进严格（**会改输出** ✗）或 `weights` 退回快数学（**那正是 F1 修掉的缺陷** ✗）⇒ **两条路都改数值** ✗ | §2.24 ✓ |

### 3.5 ✗✗ **筐 7–9 关死：K3+K5 的"新一类证否"，以及清单穷举**

★ 筐 7–9 里最像的一对是 **K3 `reformat` + K5 `rsrp`** ✓（**都是 64 线程 ✓、都只读 `h` ✓、
