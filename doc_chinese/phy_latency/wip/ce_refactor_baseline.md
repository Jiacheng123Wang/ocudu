## 3. ★ 470 µs 的三条独立读数（对账，全部指向同一结论）

| 角度 | 读数 | 结论 |
|---|---|---|
| **宿主侧**（新探针） | `iq2ce` **605.6** − `busy` **501.2** = **104.4 µs** 在设备窗口**之外** | 整段前端的宿主+等待账 **只有 ~104 µs** |
| **设备侧已知工作** | `dft_front_end` **46.6** + 车道四派发（§6.65 离线合计 **≈47**）= **≈94 µs** | `merged_hop` 的 **470 µs** 里，**≈376 µs 既不是 kernel 执行** |
| **消去法**（`p138`–`p142`） | 四族**全部**内容换成空 kernel ⇒ 窗口只从 470 掉到 442（**−5.9%**）；单族全在 **±5 µs** | **与 kernel 内容无关**（§6.164） |

⇒ **三条互不依赖的路径同时圈住同一个空洞 ≈ 376–400 µs**：它不是算力，不是宿主，也不是某一族的 kernel。
剩下的候选只有 **派发之间的非 kernel 设备开销**（依赖解析/资源绑定/同步指令）或 **执行单元的延迟受限**（访存等待）。

## 5. 改动 CE 之后怎么用这份 baseline

1. **必须再飞一条同配方的 `pNNN-n78-*`**，`OCUDU_METAL_GPU_TIME=1` + `OCUDU_UL_PHASE_SEGMENTS=1`；
2. 先核 `paired iq2ce` 的**样本数**与本节 11954 同量级（否则总体不可比）；
3. 判据顺序：**契约 9/9 → `stale=0` → V1 中位不退化 → `iq2ce`/`ce` 段是否下降 → `merged_hop` exec p50 是否下降**；
4. 方向 A（缓存 A/A⁻¹/R_hp/W）**预期省 4 个站点 ≈5 次派发/跳** ⇒ 若它有效，**`ce` 段（63.4 µs）与 `ce_weights`（37.1 µs）应当先动**；`merged_hop` 若**不动**，那正好再次印证本节第 3 条（窗口与内容无关）。
