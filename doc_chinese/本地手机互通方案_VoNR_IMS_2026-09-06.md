# 本地（OCUDU gNB + Open5GS，无外网）两部手机互通方案（2026-09-06）

> 目标：两台 5G 手机（OnePlus 8T + iPhone 17）通过本地 OCUDU gNB + Open5GS 核心网，
> 在核心网与 gNB 完全无外部网络连接的前提下，用手机原生应用互通（通话 / 信息 / FaceTime 等）。
>
> 环境事实（摘自 `doc_chinese/香港测试环境与手机接入问题总结_2026-09-05.md`）：
> - gNB：Mac（apple-silicon 分支）+ B210，n1 桥接配置 `gnb_rf_b200_fdd_n1_5mhz_bridge.yml`（iPhone 唯一成功过的配置），PLMN 00101
> - 核心网：UTM 虚拟机 192.168.31.122（桥接 192.168.64.4），open5gs 原生安装，UE 池 10.45.0.0/16、网关 10.45.0.1
> - 已通：OnePlus（IMSI 001010123456890）5G SA 注册 + `ims` DNN PDU 会话 + ping；iPhone（IMSI 001010123456789）在 n1 上曾一次性完成"注册 + ims PDU 会话 + 主动发 SIP REGISTER"（因核心网无 P-CSCF 而失败，随后 modem 策略持久化负面结果）
> - SIM：pysim 自写 sysmocom 卡，Ki/OPc 自持（789/890 可用，901 已损坏）

## 1. 结论先行（可行性矩阵）

| 能力 | OnePlus 8T（已 root） | iPhone 17（国行） | 说明 |
|---|---|---|---|
| 数据业务 | ✅ 已通 | ⚠️ 不稳定（modem 策略门控，n1 一次性成功） | 已达成，无需再改 |
| **原生拨号通话（VoNR）** | ✅ **可行（本方案主目标）** | 🔬 实验性（有成功迹象，不承诺） | 需要本地 IMS；iPhone 官方仅承诺私有网"data-only" |
| **原生信息（SMS）** | 🔶 SMSoSIP 可行，需实测 | ❌ 大概率不可用 | open5gs 主线**没有 SMSF**（NAS 短信不可用），只能走 IMS 短信 |
| **iMessage / FaceTime** | —（非苹果设备） | ❌ **硬性不可行** | 必须连接 Apple IDS/APNs 云服务，无外网 = 无可能，任何本地配置都无法绕过 |
| 第三方"准原生"通话（CallKit SIP 应用） | 不需要（原生拨号即可） | ✅ 可行（兜底方案） | Linphone / Groundwire 等经 CallKit 集成，外观接近原生电话 |
| 局域网消息 / 视频（自建 Matrix/Jitsi） | ✅ | ✅ | 真·离线 IM 与视频通话，替代 iMessage/FaceTime 体验 |

**三条铁律**（决定整个方案形态）：
1. **FaceTime / iMessage 在完全离网的孤岛中物理上不可行**——苹果这两项服务依赖 Apple IDS/APNs 云端完成身份与呼叫信令，局域网内没有离线模式。任何"本地 FaceTime"的说法都是伪命题，只能做**本地替代品**（Jitsi / Element Call 等）。
2. **Apple 官方把 iPhone 私有 5G/LTE 网络定位为"data-only"**（iOS 17+，见 Apple Platform Deployment 文档），不提供第三方启用 IMS 语音的 carrier bundle 通道。你们在香港 n1 上观察到的"iPhone 主动发 SIP REGISTER"是难得的正向信号，说明这台设备的 modem 策略**曾经**放行过 IMS 尝试——因此 iPhone 语音降级为"**值得做、但必须设低期望**的实验目标"，主验收路径放在 OnePlus 上。
3. **open5gs 主线（截至 v2.8.0）没有 SMSF**（SMS over NAS 未实现，issue #4362 仍开放，PR #2938 未合入）——所以"原生短信"只能走 **IMS 短信（SMSoSIP）** 或自行合入第三方 SMSF 分支，NAS 短信这条路直接排除。

## 2. 目标架构与网络规划

```
 ┌──────────────┐  NR-Uu(n1)  ┌─────────────────┐  NGAP/NG-U  ┌──────────────────────────────┐
 │ OnePlus 8T   │◄──────────►│ OCUDU gNB (Mac) │◄───────────►│ 核心网 VM 122 (192.168.64.4)  │
 │ IMSI ...890  │             │ B210 桥接 64.1  │             │  open5gs AMF/SMF/UPF/PCF       │
 │ MSISDN 1001  │             └─────────────────┘             │  ┌──────────────────────────┐  │
 └──────────────┘                                             │  │ 本地 IMS（同一 VM 部署）  │  │
 ┌──────────────┐                                             │  │  Kamailio P/I/S-CSCF      │  │
 │ iPhone 17    │◄──────────►                                │  │  FHoSS + MySQL           │  │
 │ IMSI ...789  │   同一小区                                   │  │  Bind9（本地 DNS）        │  │
 │ MSISDN 1002  │                                             │  │  RTPengine（媒体中继）    │  │
 └──────────────┘                                             │  └──────────────────────────┘  │
                                                              │  UPF ogstun: 10.45.0.1         │
                                                              └──────────────────────────────┘
```

**关键地址规划**（离线可用，全部落在已验证可达的路径上）：

| 项目 | 取值 | 依据 |
|---|---|---|
| UE 数据池 | 10.45.0.0/16，网关 10.45.0.1（UPF ogstun） | 现状，UE ping 10.45.0.1 已验证全通 |
| P-CSCF 地址（PCO 下发） | **10.45.0.1** | 复用 ogstun 地址，UE 到它零路由依赖；Kamailio 直接 bind 该地址 |
| UE DNS（PCO 下发） | **10.45.0.1** | Bind9 同机监听；替换 smf.yaml 默认的 8.8.8.8 |
| IMS 域 | `ims.mnc001.mcc001.3gppnetwork.org` | PLMN 00101 的标准 home domain |
| PCRF/PCEF 域 | `epc.mnc001.mcc001.3gppnetwork.org` | Rx/AAR 用（PCF 内嵌 PCRF 127.0.0.5:3868） |
| 号码 | OnePlus=1001（IMPI `001010123456890@ims...`），iPhone=1002（IMPI `001010123456789@ims...`） | FHoSS 中登记的 MSISDN，拨号互拨 |

> 部署位置：IMS 全部装进核心网 VM 122（open5gs 同机）。原因：官方教程明确 P-CSCF 的 ims_qos 模块通过 Rx 发 AAR 时使用接收报文的源 IP/端口，与核心网同机可避免 NAT 造成的 AAR 失败。VM 内 open5gs 是原生安装（非容器），ogstun 就在宿主网络栈上，Kamailio 绑定 10.45.0.1 可行。

## 3. 实施阶段

### M0：离线部署准备（先联网装完，再断网验证）

1. 在 VM 122 尚可联网时完成全部安装（或制作离线 apt 源）：
   - `mysql-server`、`bind9`、`openjdk-8/11 + ant + tomcat9`（FHoSS 需要）、`rtpengine`（或旧方案 `rtpproxy`）、编译依赖（见官方教程第 3 步清单）。
   - Kamailio 采用社区 IMS 分支：`herlesupreeth/kamailio`（5.3），配置包 `herlesupreeth/Kamailio_IMS_Config`（5.3）；HSS 采用 `herlesupreeth/FHoSS`（或纯 Python 的 `nickvsnetworking/pyhss`，省去 Java 栈，社区 5G SA 常用）。
2. **快照 VM**（UTM snapshot），之后所有变更可回滚。
3. 断网演练：核心网与 gNB 仅保留 UTM 桥（64.1↔64.4）互连（6.7 节已验证该拓扑），确认 NG Setup / 注册 / ping 仍全通。
4. 时间同步：无外网时在 VM 上跑本地 `chrony`（local stratum 源）或直接手动校时；RTPengine/IMS 不依赖 NTP 授时，此项仅为了日志与排障方便。

### M1：核心网改造（~半小时，不影响现有数据面）

1. `smf.yaml`：
   ```yaml
   smf:
     session:
       - subnet: 10.45.0.0/16
         gateway: 10.45.0.1
     dns:
       - 10.45.0.1          # 原 8.8.8.8 改为本地 Bind9
     p-cscf:
       - 10.45.0.1          # 取消注释；SMF 经 PCO 把 P-CSCF 下发给 UE
   ```
   重启 `open5gs-smfd`（若动过 UPF 绑定则连带 `open5gs-upfd`，本次不用）。
2. **PCF（推荐，非阻塞）**：启动 `open5gs-pcfd`，为 `ims` DNN 配置 QoS 策略（SIP 信令 QFI/5QI=5、语音媒体 QFI/5QI=1、GBR、高 ARP），参考 herlesupreeth 仓库 5G SA 配置（`docker_open5gs` 的 pcf/smf 目录）。若暂时不配 PCF：呼叫仍可走默认承载完成（实验室可用），只是没有专用承载与 QoS 保障。
3. 验证：重新让 OnePlus 建立 `ims` PDU 会话，抓包确认 PCO 中已带 P-CSCF 地址 10.45.0.1 与 DNS 10.45.0.1。
   - AMF 无需改动：你们的日志已证明 Registration Accept 中 IMS-VoPS=1（iPhone 才会发 SIP REGISTER）。
   - open5gs 用户 789/890 已存在且能建 ims DNN 会话，不用动 WebUI。

### M2：本地 IMS 上线（核心工程，半天）

按官方教程 [VoLTE Setup with Kamailio IMS and Open5GS](https://open5gs.org/open5gs/docs/tutorial/02-VoLTE-setup/) 在 VM 122 上实施，注意以下**离线/5G SA 适配点**：

1. **MySQL**：`kamdbctl create`；再建 `pcscf`/`scscf`/`icscf` 三库并导入教程中的 SQL；`icscf` 库写入 S-CSCF 条目：
   ```sql
   INSERT INTO nds_trusted_domains VALUES (1,'ims.mnc001.mcc001.3gppnetwork.org');
   INSERT INTO s_cscf VALUES (1,'First and only S-CSCF','sip:scscf.ims.mnc001.mcc001.3gppnetwork.org:6060');
   ```
2. **Kamailio 三实例**（P/I/S-CSCF），所有 `listen=` 与 `advertise` 用 **10.45.0.1**（不暴露 64.4/31.122）；`alias="ims.mnc001.mcc001.3gppnetwork.org"`；DBURL 按建库权限填写；RTPengine 控制套接字指向本机。
3. **FHoSS（或 pyhss）用户开通**——这是最容易出错的一步，密钥必须与 USIM 完全一致：
   | 字段 | OnePlus（1001） | iPhone（1002） |
   |---|---|---|
   | IMSI/IMSU | 001010123456890 | 001010123456789 |
   | IMPI | `001010123456890@ims.mnc001.mcc001.3gppnetwork.org` | 同理 |
   | Secret Key | = 该卡 **Ki**（pysim 写卡时记录的值） | 同理 |
   | AMF | 8000（若写卡时非默认需一致） | 同理 |
   | OP | 11111111111111111111111111111111（若卡用自定义 OPc 需换算/一致） | 同理 |
   | SQN | 000000021090（**远高于当前 USIM 使用量**，防 AKA 同步失败；SIM 侧支持的话用 sysmo-usim-tool 关闭 SQN 校验更稳） | 同理 |
   | IMPU | `sip:001010123456890@ims...` + `sip:1001@ims...` + `tel:1001`，后两者绑定到隐式集 | 同理（1002） |
   | Visited Network | `ims.mnc001.mcc001.3gppnetwork.org` | 同理 |
4. **Bind9**：zone `ims.mnc001.mcc001.3gppnetwork.org`（pcscf/icscf/scscf A+SRV 全部指 10.45.0.1，端口 5060/4060/6060）与 `epc.mnc001.mcc001.3gppnetwork.org`（pcrf 127.0.0.5）；`listen` 包含 10.45.0.1；关闭 dnssec-validation，allow-query any。
5. **RTPengine**：`interface = 10.45.0.1`，`listen-ng = 127.0.0.1:2223`；pcscf 配置中 `rtpengine_sock` 对应改。
6. **Rx 对接**：pcscf 配置/freeDiameter 中添加 ConnectPeer `pcscf.ims.mnc001.mcc001.3gppnetwork.org`（10.45.0.1），对端 PCRF=127.0.0.5:3868、realm `epc.mnc001.mcc001.3gppnetwork.org`；open5gs 侧 freeDiameter/pcf 配置相应 peer。
7. 启动顺序：bind9 → mysql → FHoSS → p/cscf、i/cscf、s/cscf（三个 `kamailio -f ... -E`）→ rtpengine。

### M3：OnePlus VoNR 原生通话验收（主目标）

1. OnePlus 8T APN 保持：`internet`（default）+ `ims`（ims 类型）——已具备。
2. **强制 IMS**（root 已有）：按 [CoIMS_Wiki](https://github.com/herlesupreeth/CoIMS_Wiki) 思路，或直接设属性（社区 8T/ColorOS 常用）：
   ```
   persist.dbg.ims_volte_enable=1
   persist.dbg.volte_avail_ovr=1
   persist.dbg.vt_avail_ovr=1
   persist.dbg.wfc_avail_ovr=1
   ```
   （VoNR 相关属性按基带实际情况补，`*#*#4636#*#*` → Phone Information 里确认 IMS Status=Registered、Voice Network Type=NR。）
3. 抓包验收（VM 上）：
   ```bash
   sudo tcpdump -i ogstun -w /tmp/ims.pcap 'port 5060 or port 4060 or port 6060'
   tail -f /var/log/open5gs/{amf,smf,pcf}.log
   ```
   检查点：REGISTER→401 挑战→带 AKA 响应的 REGISTER→200 OK；`kamcmd`/pcscf 日志中出现 890 的 IMPI；FHoSS 中 IMPU 状态 Registered。
4. 拨测：1001 ↔ 1002 互拨（拨短号 1002 即可，S-CSCF 按 IMPU 查找路由）：
   - SIP：INVITE → 183 → 200 OK → ACK → BYE；
   - 媒体：rtpengine 会话统计中出现双向 RTP 流（`rtpengine-ctl list`），双方听到声音；
   - QoS（若启用 PCF）：观察 OCUDU 日志中 PDU Session Resource Modify 与 QFI 1/5 专用 DRB 建立——**这也是对 OCUDU gNB 的 QoS 流能力的一次实测**（见风险 R4）。
5. **SMS over IP（SMSoSIP）**：OnePlus 原生"信息"应用互发短号短信，看 S-CSCF 是否路由 MESSAGE；不通则查 IMS 短信能力开关（CoIMS 强制后一般可用）。open5gs 主线无 SMSF，这是唯一原生短信路径。

### M4：iPhone 实验（低期望，保数据）

1. **顺序很重要**：等 IMS 完全就绪后，再让 iPhone 接入（避免它再次把"无 IMS 网络"记入持久负面状态——6.11 节教训）。用其唯一成功过的 n1 桥接配置，**不要中途改频点/PCI/PLMN**。
2. 观察 pcscf 日志中 IMSI 789 的 IMPI 是否发 REGISTER 并完成 AKA。两种结局：
   - **成功**（有 6.11 节 SIP REGISTER 的前科，存在概率）：iPhone 原生电话 App 走 VoNR 互拨 1001/1002；Messages 短信能否通取决于 iOS 是否放行 SMSoSIP（Apple 文档口径是 data-only，不承诺）。
   - **失败**（更可能）：按 Apple 官方定位（私有网 data-only）接受现实，iPhone 语音降级为兜底方案。
3. 兜底（体验接近原生）：安装 **CallKit 型 SIP 软电话**（Linphone/Groundwire/PortSIP，App Store 在有网时装好），注册到本地 Kamailio（用户名=1002，服务器=10.45.0.1）——CallKit 使其来电/去电进入系统通话界面与"最近通话"列表。通话效果与原生无异，只是 App 不同。
4. 长期改善 iPhone 数据接入稳定性：沿用 6.12 节既定路线（SJA5 卡 + 999 IMSI + DF.5GS + SUCI 文件 + 99901 网络），并对照 Apple 私有 5G SA 要求核查：SUCI 非空保护、NEA 非空加密、必要时 NID 广播（**OCUDU 侧需确认是否支持 NID 配置**——当前 configs 中未发现 nid 字段，若走 999 路线需要评估）。

### M5：离线消息 / 视频（iMessage、FaceTime 的本地替代）

| 需求 | 替代方案 | 部署要点 |
|---|---|---|
| 消息（文字/图片/文件） | Matrix Synapse/Dendrite + Element（两端均有原生 App） | 装在 VM 122 或另开小 VM，域名用本地 DNS 解析（如 `chat.local`→10.45.0.1 或 64.4），TLS 用自签证书 |
| 视频通话 | Jitsi Meet（自建）或 Matrix Element Call（SFU） | 同机 docker 部署；两端用浏览器或 App 加入，媒体走 UE→UPF→服务器中转 |
| 轻量 IM | XMPP：Prosody + Conversations(Android)/Monal(iOS) | 最简单，资源占用最小，适合 VM 资源紧张时 |

这些服务全部经 UE 的 10.45.0.0/16 数据面互访，不依赖任何外网。

## 5. 风险与备选

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | OnePlus 8T 无法开启 VoNR（X55 基带 + ColorOS 组合问题） | 原生通话失败 | CoIMS/属性强制；若仍不行，换社区 VoNR 验证过的机型（Pixel 6+ / 三星 S21+ / OnePlus 9 等）；或退回"SIP 软电话兜底" |

## 7. 定位说明：为什么不直接用 Wi-Fi 热点（2026-09-06 补充）

**就"两台 iPhone 应用层互通"这一目标而言，Wi-Fi 直连完胜**：AirDrop 连热点都不需要（AWDL 点对点），局域网应用一个路由器即可，SIM/核心网/gNB 全部省掉。FaceTime/iMessage 在 Wi-Fi 下同样依赖苹果云——两机互通的诉求与 5G 无关。

**但私有 5G 卖的是网络属性，不是设备互通**：

| 维度 | Wi-Fi 热点 | 私有 5G |
|---|---|---|
| 覆盖/移动性 | 几十米，无漫游 | 数百米/小区，多 gNB 无缝切换（OCUDU 多 gNB 教程） |
| 时延确定性 | 竞争接入，拥塞不可预测 | 调度 + 5QI/GBR，TDD 可上行主导 |
| 鉴权 | 共享 PSK | USIM AKA 双向鉴权 + SUCI，一卡一策略 |
| 规模 | 数十台退化 | 单小区数千台、独立 SLA |
| 频谱 | 公共频段不可控 | 授权/共享频谱可控（HK n78 3.6 GHz 以上干净） |

Apple 对 iPhone 私有网的支持同样按"企业数据终端"定位：私有网 SIM 跑数据 + 运营商 SIM 管语音的双卡模型、地理围栏切换、iOS 18 的 Wi-Fi Calling over cellular（运营商语音借私有 5G 数据通道承载）。**data-only 是特性而非缺陷**，与实验中 iPhone 拒绝正常 IMS 注册的现象一致。

**本项目（OCUDU）的正确定位**：RAN 产品，手机是 UE 测试载体。"手机互通"不是私有 5G 卖点；值得 demo 的是 Wi-Fi 做不到的能力——跨 gNB 移动会话不中断、高密度并发、上行确定性业务、QoS 流与切片隔离。
