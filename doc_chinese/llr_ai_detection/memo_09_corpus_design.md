# AI LLR Detection 语料设计与采集方案（memo 09）

> **定位**：这是一份**长期、迭代**的方案，不是一次采集任务的说明书。
> 语料是这条工作流**唯一会持续增值的资产**；模型会重训、架构会改，语料不会重来。
>
> 用户裁定（2026-10-08）：
> - **"语料可以补充采集，并且在代价许可的范围内可以不受限"**；
> - **"这是一个长期的工作，并且在开发过程中还需要不断的补充、调整"**。
>
> 版本：v1.0 ｜ 日期：2026-10-08 ｜ 上位文档：主规划 §3.1、§0.2(3)、`memo_04`

---

## 0. 三条贯穿全篇的原则

| # | 原则 | 为什么 |
|---|---|---|
| **1** | ★★ **采集期不可恢复的字段，必须在采集期记录** | 网格、PDU、几何、TB、环境元数据**事后无法重建**；事后补记 = 重飞一次 |
| **2** | ★★ **语料的规模由"部署环境的覆盖需要"决定，不由"手头有什么"决定** | `memo_04` v1.0 曾把现有 17.7 万次接收当成上界，那是错的 |
| **3** | ★★ **每一次采集都要有"声明的意图"，并与一次飞行绑定** | 否则语料会变成"顺便录的一堆东西"，无法回答"这个维度够不够" |

## 1. 为什么语料设计必须先于模型设计

> 用户在 AI CE 线上的原话：
> **"我们在 AI CE 里面踩过最大的坑就是'训练环境不等于部署环境'，
> 以至于得到负面的结论（其实不是负面，只是我们没有更进一步投入资源深挖）。"**

★★ 这条教训有两个层面，语料方案必须同时回应：

| 层面 | 内容 | 语料方案如何回应 |
|---|---|---|
| **技术** | **训练分布 ≠ 部署分布**是 AI PHY 的头号失效模式 | §5 的覆盖维度**以部署实测为锚**，并**显式包含边界与分布外**（§5.3） |
| **方法论** | ★★ **当年的"负面结论"成因是投入不足，不是方法失败** | §10 的**迭代流程**把"语料够不够"变成一个**持续可回答的问题**，而不是一次性假设 |

★ 独立佐证（文献）：Nokia 的 OTA 研究发现 LOS 训练的 DeepRx *"failed the over-the-air tests
despite converging well during training"*，且**宽随机化胜过参数匹配**
（`memo_03` §7bis.G.4）。⇒ **覆盖 > 拟合**。

## 2. 现状：两套采集设施，**单独用都不够**

（`memo_04` §1 + 本次代码核查）

| | **系统 A：`ul_capture`** | **系统 B：G-5 hook（`OCUDU_HELENA_DUMP_DIR`）** |
|---|---|---|
| 编译门 | ★ `ENABLE_UL_CAPTURE`，**默认 OFF** | **始终编译在内** |
| 触发 | `OCUDU_UL_DUMP=<prefix>` | `OCUDU_HELENA_DUMP_DIR=<dir>` |
| 条数上限 | ★★ **`OCUDU_UL_DUMP_COUNT` 默认 8** | **无上限** |
| 文件 | `<key>.txt` / `.bin` / `_ce.txt` / `_h.bin` / `_llr.bin` | `rx_*.f32` / `dump_*.f32` / `tb_*.bits` / `rx_meta.csv` / `dd_meta.csv` / `meta.csv` |
| 接收网格 | ✅ `.bin` | ✅ `rx_*.f32` |
| **PDU 元数据** | ★ **完整**（含 `n_id`、`dmrs_type`、`dmrs_scrambling_id`、`dmrs_n_scid`、`dmrs_nof_cdm_groups_without_data`、`rv`、`tbs_lbrm`、`dc_position`…） | ⚠ **不全**（`rx_meta.csv` 16 列，**缺 `dmrs_type` / `nof_cdm_groups_without_data`**） |
| **TB 标签** | ❌ **没有** | ✅ `tb_*.bits` + `dd_meta.csv`（仅 CRC-OK） |
| 经典 LLR | ✅ `_llr.bin`（★ 解扰**后**） | ❌（可由 TB 离线重算） |
| CE 输出 | ✅ `_h.bin` + `_ce.txt` | ✅ `dump_*.f32` + `meta.csv` |
| `n_rapid`（msgA） | ❌ | ❌ |

### 2.1 三条结论

1. ★★ **必须定义一个"规范记录"格式**（§7），它是两套的超集——
   **A 的元数据完整性 + B 的无上限与 TB 标签**；
2. ★ **实现上应当挂在"始终编译在内"的那一套上**（B 风格），
   因为 A 的 `ENABLE_UL_CAPTURE=OFF` 默认意味着**线上构建根本不采集**，
   而语料是长期资产，不能依赖一个默认关闭的编译开关；
3. ★ **三处已知缺字段必须在设计里补上**：`dmrs_type`、`nof_cdm_groups_without_data`、`n_rapid`。

## 3. ★★ 语料的三层结构

| 层 | 来源 | 规模 | 成本 | 用途 | 局限 |
|---|---|---|---|---|---|
| **T0 仿真** | 自建 / Sionna / aerial 的 `FadingChannel`（TDL/CDL, TR 38.901） | **不限** | 低 | 覆盖**大范围**信道/SNR/MCS 组合；消融实验；架构搜索 | ★ **不是部署环境** ⇒ 只能作**预训练与消融**，不能单独作为结论依据 |
| **T1 OTA** | **飞行腿**（`fly_leg.sh` 系列）绑定采集 | 受飞行时间限制 | 高 | ★★ **部署环境的唯一来源**；微调；**最终评测** | 覆盖慢、不可复现（信道不可重放） |
| **T2 持续** | 开发过程中的常开采集（低速率、长期） | 中 | 低（搭车） | ★ **漂移监测**（环境/温度/时段/固件变化）；发现"训练时没见过的情形" | 需要存储与治理 |

★★ **关键纪律**：
- **T0 只能用于预训练与消融**，任何"我们的方法更好"的结论**必须由 T1 支撑**（主规划 §0.2(3)：OTA 是最终裁决者）；
- ★ **T0/T1 必须同分布可比**：仿真要按 §5 的同一套覆盖维度生成，否则"仿真 vs OTA"不是一个受控变量。

## 4. ★★★ 记录字段清单（本方案的核心）

**"采集期不可恢复"= 一旦当次没记，事后只能重飞。** 这一列决定了实现顺序。

### 4.1 A 组：观测量

| 字段 | 说明 | 采集期不可恢复 |
|---|---|---|
| `rx_grid` | **整个 slot** 的接收网格，`[port, symbol, subcarrier]`，**全部接收端口** | ★★ **是** |
| 网格布局标识 | 元素类型（CBF16 / CF32）、维度顺序、stride | ★★ 是（必须随记录存，不能靠约定） |
| 采样率 / FFT 配置 | `scs_khz`、`fft_size`、guard、`bwp_start_rb`、`bwp_size_rb` | ★★ 是 |

### 4.2 B 组：几何（★ 现在缺两项）

| 字段 | 说明 | 采集期不可恢复 |
|---|---|---|
| `dmrs.coordinates` | 每个导频的 `(symbol, subcarrier)` | ★★ 是 |
| `dmrs.reference_symbols` | 已知的 DM-RS 符号值 | ★★ 是（由序列生成，但依赖配置） |
| `dmrs.symbol_mask` | 哪些 OFDM 符号是 DM-RS | ★★ 是 |
| **`dmrs_type`** | ★ **现在没记** | ★★ **是** |
| **`nof_cdm_groups_without_data`** | ★ **现在没记** | ★★ **是** |
| `dmrs_add_ln_pos` | 附加 DM-RS 位置 | ★★ 是 |
| `dmrs_scrambling_id` / `n_scid` | 序列参数 | ★★ 是 |
| `pusch.data_re_indices` | 要出 LLR 的 data RE 索引 | 可由 B+分配重算，但**存下来更省事** |

### 4.3 C 组：PDU 配置

`slot`、`frame`、`rnti`、**`n_id`**、★ **`n_rapid`**（msgA，现在没记）、`scid`、`data_scid`、
`rv`、`mcs_index`、`mcs_table`、`modulation`、`target_code_rate`、`nof_tx_layers`、
`rx_ports`、`rb_mask`（或 `alloc_nof_rb` + `alloc_prb`）、`start_symbol_index`、`nof_symbols`、
`dc_position`、`enable_transform_precoding`、`tbs_lbrm`、`harq_id`、`new_data`。

### 4.4 D 组：标签（★ 这一组的"负样本"也要记）

| 字段 | 说明 | 采集期不可恢复 |
|---|---|---|
| `tb.bits` | **仅 CRC-OK** 的传输块比特 | ★★ 是（★ 但见下） |
| **CRC 状态** | ★★ **CRC-KO 的接收也要记录并标状态** | ★★ 是 |
| `nof_codeblocks` | 码块数 | ★★ 是 |

★★ **为什么 CRC-KO 也要记**：它们是**部署分布的一部分**——只留 CRC-OK 会**系统性地删掉低 SNR 与深衰落样本**，
这正是 AI CE 那类"训练集比部署环境乐观"的成因之一。**负样本可以没有真值标签，但必须有。**
（用法：作**无监督/一致性**评估集，以及作"经典链也失败"的对照。）

### 4.5 E 组：经典链中间量（★ 用于基线、蒸馏与归因）

| 字段 | 说明 |
|---|---|
| LS 信道估计（导频处） | ★ 网络输入的一部分（主规划 §2.2.1） |
| 后均衡噪声方差 | ★ 上报义务（主规划 §2.3） |
| 均衡符号 | 对照与消融 |
| **经典 LLR** | ★ 基线对拍 + 蒸馏热身 |
| ★ **生成它们的二进制 stamp** | ★★ **必须记**——否则这些中间量**不可复现**（同一份源码在不同构建下会产生不同 bf16 比特，`metal_kernel_fusion` §2.27 的教训） |

### 4.6 F 组：信道与上报量

`noise_variance`、`snr`、`rsrp`、`epre`、`ta_us`、`cfo_hz`（逐端口）。
★ 记下来可用于：① 分层统计；② 检查"上报量 vs 部署表现"的关系；③ 深度 3 的上报义务回归测试。

### 4.7 G 组：环境与血缘（★ 最容易被忽略，却决定语料能否被信任）

| 字段 | 为什么必须 |
|---|---|
| 绝对时间（单调 + 墙上时钟） | 与温度/时段/负载关联；热降频分析 |
| 站点 / 小区 / gNB 标识 | ★ 泛化性按**站点**评估，不能按随机划分 |
| UE 标识与型号 | 不同 UE 的发射特性不同 |
| ★ **二进制 stamp / commit** | ★★ **任何中间量都依赖它** |
| 配置 hash（YAML + env knobs） | 复现前提 |
| 飞行腿标签（`mkf0NN-...`） | 与 leg 记录对齐 |
| 采集意图 ID | 见 §8 |
| （若能取到）芯片温度 / 功耗状态 | C11 的测量可复现性问题（热降频 3.3×，`platform_portability_design_rules.md` C11） |

## 5. 覆盖维度与配额

### 5.1 锚点：我们已实测的部署分布（`memo_04` §2）

| 维度 | 实测（`oaiue_helena_retest` 152,874 次） | 实测（`site6_0831` 75,183 次） |
|---|---|---|
| SNR | 均值 **16.8 dB**（83% 在 15–20 dB） | 均值 19.2 dB |
| 带宽 | 25/50/51/46/44/43 PRB | 51/25/43/50/46 |
| 调制 | 16QAM 58% / 64QAM 36% / QPSK 5.7% | 256QAM 50% / QPSK 19% |
| 层数 | **全部 1（SISO）** | — |
| DM-RS | **全部 {2,7,11}** | — |

### 5.2 训练语料的覆盖维度（T0 + T1 同一套）

| 维度 | 取值 | 备注 |
|---|---|---|
| SNR / Es-N0 | **0–30 dB，步长 2 dB** | 覆盖实测区间**并向两侧外扩** |
| 带宽 | 1 / 2 / 4 / 6 / 11 / 18 / 25 / 36 / 51 / 106 / 273 PRB | ★ **窄分配专门覆盖**（经典链在窄带最弱） |
| 调制 | QPSK / 16QAM / 64QAM / 256QAM | 逐调制分别达标（G3） |
| 层数 | 1 / 2 | SISO 是部署主体；2 层为 MIMO 预留 |
| 接收端口 | 1 / 2 / 4 | |
| DM-RS | type 1/2 × 1/2 CDM × addPos 0–3 × 2/3/4 符号 | ★ 平台的准入包络（`memo_06` §1.3bis） |
| 信道（T0） | TDL-A…E、CDL-A…E | TR 38.901 |
| LOS/NLOS（T1） | 两者都要 | ★ 文献里 LOS→NLOS 是已知失效点 |
| Doppler | 0 / 5 / 30 / 100 / 500 Hz | ★ 500 Hz 是"经典先崩"的区间（`memo_03` §7bis.G.3） |
| 干扰 | 无 / 邻区加扰 | |
| 站点 | **≥2 个**（现有 site1/…/site6 + oaiue） | ★ 泛化性按站点划分 |

### 5.3 ★★ 必须显式包含"边界与分布外"

| 类别 | 例子 | 为什么 |
|---|---|---|
| 窄带 | 1–6 PRB | 经典链最弱处；也是"AI 可能赢"的候选区 |
| 低 SNR | 0–10 dB | 训练集如果只覆盖 15–20 dB，模型在边缘会崩 |
| 少导频 | 2 个 DM-RS 符号 / addPos=0 | 论文收益最大的区间（`memo_02` §3.1） |
| 高 Doppler | 100–500 Hz | 经典链先崩的区间 |
| **msgA** | `n_rapid` 非空 | ★ 需要先补上这个字段的采集 |
| **DMRS AddPos=2** | 分布外配置 | ★ 文献实测：神经接收机在此**静默钉在 100% BLER**（`memo_03` §7bis.G.2）——**必须作为专门的鲁棒性测试集** |
| 异常/退化 | 深衰落、饱和、丢样点 | |

## 6. ★ 覆盖度追踪：把"缺什么"变成一张可读的表

★★ **本方案的核心机制**：语料不是"一堆文件"，而是一个**带覆盖度账本的资产**。

```
corpus/
  index.parquet          ← 全部记录的标量元数据（可 SQL 查询）
  coverage.json          ← ★ 覆盖度账本：每个维度 × 每个取值的计数与目标
  gap.md                 ← ★ 自动生成："还缺什么，缺多少，需要哪条腿"
  sessions/<session>/…   ← 记录本体（§7）
```

**覆盖度账本的形状**（示意，实现时用脚本生成）：

| 维度 | 取值 | 目标 | 现有 | 缺口 | 计划来源 |
|---|---|---|---|---|---|
| SNR × 调制 | 10 dB × 16QAM | 2000 | 340 | **1660** | 下次飞行（T1）/ 仿真（T0） |
| 带宽 | 6 PRB | 1000 | 0 | **1000** | ★ **需窄带授权配置** |
| DM-RS | type2 | 500 | 0 | **500** | ★ **需采集字段补齐后** |
| msgA | `n_rapid` 非空 | 200 | **不可采** | — | ★ **阻塞：字段未记录** |

★ **每次飞行前先读 `gap.md`**，飞行后更新账本（§8、§10）。

## 7. 格式与存储：规范记录

★ 形状**借用 aerial 的做法**（parquet 索引 + 每条记录若干文件，`memo_05` §1.5），
内容用**平台契约的字段名**（`memo_06` §1），使三个来源可以互相对照。

```
<corpus>/<session>/<key>/
  meta.json           ← 全部标量元数据（A/B/C/D/G 组的非张量部分）
  rx_grid.bin         ← CBF16 或 CF32，[port, symbol, subcarrier]
  dmrs_coords.bin     ← U16 [nof_pilots, 2]        (symbol, subcarrier)
  dmrs_refs.bin       ← CF32 [layer, pilot]
  data_re_idx.bin     ← U32 [nof_data_re]
  tb.bits             ← 仅 CRC-OK；CRC-KO 时不存在，但 meta.json 里 crc=ko
  ls_est.bin          ← 可选（E 组）
  post_eq_noise.bin   ← 可选（E 组）
  eq_symbols.bin      ← 可选（E 组）
  classical_llr.bin   ← 可选（E 组，★ 解扰前，与模型输出同域）
```

**格式纪律**：
1. ★★ **每条记录自带布局标识**（元素类型/维度顺序/stride 写进 `meta.json`），
   **不靠全局约定**——约定会随代码漂移；
2. ★ ★ **`classical_llr.bin` 存"解扰前"**，与模型输出的域一致（`memo_01` §3）；
   若同时要解扰后的，另存一个字段而**不是覆盖**；
3. ★ **字段只增不改**（向后兼容）；退役字段标 `deprecated` 而不删；
4. ★ **小端、无对齐填充**；张量一律 `[dim0, dim1, …]` 行主序，写进 `meta.json`。

## 8. ★★ 与飞行的绑定：每腿声明"采集意图"

★ 每次飞行（`fly_leg.sh`）**必须先声明意图**，否则不采：

```yaml
# capture_intent.yaml —— 随 leg 一起记录
intent_id: ci-0007
leg: mkf0NN-...
goal: "补 SNR 10-15 dB × 16QAM × 25 PRB 的 T1 样本"
target_dimension: {snr_db: [10, 15], modulation: 16QAM, nof_prb: 25}
expected_records: 500
knobs:
  OCUDU_CORPUS_DIR: /path/to/corpus/sessions/2026-10-08-mkf0NN
  ...
result:                       # 飞行后回填
  captured: 612
  coverage_delta: "snr 10-15 × 16QAM: 340 → 952"
```

★★ **这样做的三个好处**：
1. 每次飞行都产生**可审计的覆盖度增量**，而不是"顺便录了点东西"；
2. **缺口驱动飞行配置**（要采窄带就先改授权，而不是飞完才发现没有）；
3. ★ 与 `metal_kernel_fusion` 的 leg 纪律一致——**每个数字可追溯到一次 leg**。

## 9. 版本与血缘

| 概念 | 做法 |
|---|---|
| **语料版本** | `<corpus>/VERSION`，形如 `2026.10.r1`；**任何模型必须能说出它训在哪个版本上** |
| **模型卡** | 每个训练产物附：语料版本、覆盖度账本快照、训练/验证/测试的**划分规则**、二进制 stamp |
| ★ **划分规则** | ★★ **按站点 + 按时间会话划分，禁止随机划分**（同一信道的相邻 slot 会造成泄漏）。划分脚本要**打印对照表**（训练/测试的 slot 范围、rnti、PRB/调制/SNR 分布不重叠） |
| **不可复现声明** | ★ 记录"哪些字段依赖二进制版本"（E 组中间量），并在模型卡里标注 |

## 10. ★ 迭代流程（三个回路）

```
① 飞行回路（每次飞腿）
   读 gap.md → 定 capture_intent → 飞 → 回填覆盖度 → 更新 index/coverage

② 评测回路（每次 G 门禁）
   在 T1 测试集上评测 → 发现"某个维度表现异常" → 反查覆盖度 →
   若该维度样本不足 ⇒ 新增采集意图；若样本够但仍差 ⇒ 记为模型问题

③ 模型回路（每次模型迭代）
   新架构可能需要新输入字段 ⇒ 先加到采集（字段只增不改）→ 重采一批 →
   再训。★ 禁止"先用现有字段凑，以后再补"——那正是不可恢复字段丢失的路径
```

★ **每次回路结束都要更新 `gap.md`**，它是"语料够不够"这个问题的**唯一权威回答**。

## 12. 纪律与风险

| # | 纪律 / 风险 | 应对 |
|---|---|---|
| 1 | ★★ **语料不落 git** | 遵守 `doc_chinese/.gitignore` 的"工作材料"纪律；**入库的是方案、覆盖度账本与索引**（小） |
| 2 | ★★ **存储预算** | 网格是主要成本：51 PRB × 14 符号 × 1 端口 × CF32 ≈ 57 KB/条 ⇒ 10 万条 ≈ 5.7 GB。**T2 常开采集必须降采样或轮转** |
| 3 | ★ **不可复现**（信道不可重放） | T1 样本**只能用一次**做测试集；**任何调参都会污染它** ⇒ 预留**封存的测试集**，只在 G 门禁时打开 |
| 4 | ★ **E 组中间量依赖二进制版本** | 每次采集记 stamp；跨版本比较时先验证 |
| 5 | **采集影响实时性** | 采集本身有成本（平台记录：Class-C 内联拷贝 ~734 KB、50–100 µs/slot）。⇒ **T1 采集与性能腿分开飞**，不要在测性能的腿上开重采集 |
| 6 | ★ **字段漂移** | "字段只增不改" + `meta.json` 自带布局标识 + 索引里带 schema 版本 |
| 7 | ★ **覆盖度账本会腐化** | 由脚本从 `index.parquet` **重新生成**，不手工维护（同 `ocudu_env_knobs_inventory_and_leg_whitelist.md` 的"GENERATED，never hand-edit"纪律） |
