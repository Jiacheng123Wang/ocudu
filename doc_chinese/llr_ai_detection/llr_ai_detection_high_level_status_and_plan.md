# AI LLR Detection —— 高层现状与规划

> **一句话**：把 5G NR 上行 PUSCH 接收链的「**信道估计 + 均衡 + 解映射**」换成一个
> **神经前向**，输入是 DFT 后的时频网格**及其几何**，输出是**解扰前的软比特（LLR）**，
> 交给现有 LDPC 译码器；**在 Apple Silicon 上真实跑起来，并用空口实测说话**。
>
> **配套文档**：详细设计与实施步骤在 `llr_ai_detection_design_and_implementation.md`（活文档）；
> 调研证据在 `memo_01`–`memo_09`；工作约定在 `wip/README.md`。
>
> 版本：v1.0 ｜ 状态：**调研完成，设计就绪，未开工** ｜ 日期：2026-10-08

### 0.3 ★★ 三盆冷水（必须在开工前记住）

1. **AI CE 的"负面结论"实为投入不足**——成因是**训练环境 ≠ 部署环境**，不是方法失败。

## 1. 现状调研（全部来自代码与实测）

### 1.1 调研成果一览

| # | 范围 | 关键结论 | 产出 |
|---|---|---|---|
| 1 | **仓库自身的接缝与 LLR 契约** | 接缝有**两种深度**；深度 3（CE+均衡+解映射）才是标准 neural receiver 形态 | `memo_01` |
| 2 | **参考论文 DEFINED** | 0.42 M GPT-2，星座分类 + 判决反馈；★ **收益全在极少导频区**；**无任何时延数据**，检测自回归串行 | `memo_02` |
| 3 | **公开文献 7 条线** | ★ **ANE 不能做逐符号引擎但可以做每跳一次**；LLR 校准是成熟问题；**"AI-native PHY"在生产里只有 1 个模块** | `memo_03` + `survey/`（11 份 + 38 篇 PDF） |
| 4 | **数据、标签与工作点** | ★ **工作点实测**（见 §0.2）；两套采集设施**单独用都不够** | `memo_04` |
| 5 | **NVIDIA aerial** | ★ 仓库里带着**两个训练好的 ONNX**（LLRNet 184 参数 / neural_rx 145 232 参数）与**完整 ML 流程**；★ **没有任何一条推理路径做到零拷贝** | `memo_05` |
| 6 | **OCUDU dApp 平台 5 仓** | ★★ **找到生产级的深度 3 契约与接缝**；两个硬约束（**噪声头是必需的**、模型产物 ≤1 MiB）；Metal 后端有两处结构性阻塞 | `memo_06` |
| 9 | **语料设计与采集方案** | 三层结构 T0/T1/T2、**采集期不可恢复字段清单**、覆盖度账本、与飞行绑定 | `memo_09` |

### 1.2 ★★ 最有价值的三个发现

**① 宿主契约与我们设计的完全一致**（`memo_06` §1）——
输入 `rx_grid + pusch + dmrs`、输出**解扰前** LLR、"**positive values favor bit zero**"。
**三个独立平台（我们的链、OCUDU dApp、NVIDIA aerial）在同一个符号约定上收敛。**

**② 深度 3 是官方支持的扩展点**（`memo_06` §3）——
SDK 的 `extension_model.md` 把 Receiver 的可替换核心直接写成
*"**joint CE/EQ/demapping, learned receiver stages**"*，且其输出契约规定为
`[data_re, layer, bit]` **FP16 解扰前 LLR**。

**③ 系统在 3000+ µs 的 LDPC 下仍能 OTA 工作**（§0.2）——
这条**第一手实测**推翻了本仓库此前所有"时隙预算"讨论的隐含前提，
也印证了平台自己写的 *"Not a 3GPP slot deadline"*（默认 2000 µs）。

## 2. 目标与判据（★ **预登记**，判读前不得更改）

### 2.1 两个目标必须分开排序，否则一定会自欺

| | 目标 | 内容 | 状态 |
|---|---|---|---|
| **G-A** | **时延** | `ce` + `eqdem` 两段 → 一次神经前向 + 同步开销，**OTA 结果不明显劣化** | **第一目标** |
| **G-B** | **精度** | 在少导频 / 高阶调制区间**超过**经典 MMSE + LLR | ★ **待证伪的第二目标**，由 P0 裁决 |

★ **为什么必须分开**：若把两者混在一起讲，P0 一旦显示精度空间很小，
整个工作流会被误判为失败——**而它其实可能仍然值钱（时延）**。

### 2.2 ★★ 唯一的硬约束（不是性能指标，是方法论指标）

> **"主要的限制是要能够进行飞腿实验，拿到 OTA 的第一手资料，
> 而不是像学术论文那样，仅仅是仿真结果。"**（用户，2026-10-08）

⇒ 链路必须**每一步都 OTA 可飞**；**最终裁决者是空口数据，不是仿真曲线**。
这也解释了为什么"经典路径始终在链上"是设计不变式 I1，而不只是稳健性措施。

### 2.3 门禁 G0–G6（详见设计 §4）

| 门 | 内容 | 预登记判据要点 |
|---|---|---|
| **G0** | ★ **P0：值不值得做** | 给出"检测环节可改善空间"的**量化上界**；**若上界很小 ⇒ 只保留 G-A 或终止** |
| **G1** | 语料与标签管线 | 可一键复现；**泄漏检查通过**（按站点+时间划分）；经典链基线已记录 |
| **G2** | 单网络（深度 3）离线训练 | ★ **主指标 = 真实 LDPC 之后的 coded BLER**（互信息不能预测 BLER）；标度校准后 CRC 不掉 |
| **G3** | 全调制 + 多任务头 + 消融 | 逐调制分别达标；**噪声头不得输出近零常数**；量化曲线 |
| **G4** | 接链 | 契约测试全过；开关关闭时**bit-exact**；打开时 CRC ≥ 参考 |
| **G5** | 端到端时延 | ★ **OTA 结果不劣化** + 完整时延分布（含同步）+ **写明争用条件** |
| **G6** | OTA 实测 A/B | ★ **side-by-side SER/BLER**（平台明文说这份证据不在开放阶梯内） |

★ **G5 的判据已按 §0.2 的实测事实改写**：从"p99 ≤ 某个 µs 数"改为
"① OTA 不劣化 ② 给出发动机时延分布 ③ 若超时隙，说明它为何仍能工作"。

## 3. 收益从哪里来（假设 + 各自的验证方式）

★ **三条假设，都必须可证伪**；没有一条被当作前提。

| # | 假设 | 为什么可能成立 | 怎么验 |
|---|---|---|---|
| **H1** | ★ **联合优于分步** | 经典链是"线性 MMSE 均衡 → **逐 RE 独立**解映射"；"逐 RE 独立"是近似。联合网络可以对整个网格**联合**推断 | **P0-c**：genie 上界给出**可改善的全部空间** |
| **H2** | ★ **少导频/窄带是高收益区** | 论文的收益集中在极少导频；经典链在导频稀疏与窄带处最弱 | **P0-a**：经典链的导频密度扫描；**P0-b**：SNR 扫描 |
| **H3** | ★ **时延**：eqdem 的 667 µs 里大部分不是算力 | 本仓库已证：`metal_kernel_fusion` 的"一格 667 µs 里只有几十 µs 是算力"；且 NVIDIA 同类内联实现实测 **81.6/112 µs**（51 PRB/2 端口） | **P4/P5**：端到端时延分布 |

★ **反过来的可能**：若 H1/H2 都不成立（P0 显示空间很小），
**工作流收缩到 H3（时延）**，或**如实记录为"在我们的工作点上，联合检测的精度收益不存在"**——
后者本身仍是有价值的结论（它把论文的适用边界量化了）。

## 4. 高层架构设计

### 4.1 形态：**一个网络，深度 3**

```
                   ┌────────────────────────┐
 时频网格 (CBF16) ─┤                        ├─► 主头：逐 RE 逐比特 LLR（解扰前）
 DM-RS 坐标 (U16) ─┤      共享 trunk         ├─► 辅头：后均衡噪声方差  ★ 必需（主机 SINR 唯一来源）
 DM-RS 参考符号 ───┤   (2D conv / ResNet)    ├─► 辅头：信道估计 + 噪声（供经典测量核）
 data RE 索引 ─────┤                        │
 PUSCH 元数据 ─────┘                        │
                   └────────────────────────┘
```

★ **为什么是一个网络而不是两个**（设计不变式 I4）：中间的信道估计会成为**有损瓶颈**、
断掉端到端梯度，且每多一个网络多付一次 dispatch 地板。

★ **关键设计选择**：**导频处的经典 LS 估计作为输入**（工业形态），
网络学的是"插值 + 噪声估计 + 均衡 + 解映射"的**联合**，而不是从零学信道估计。

### 4.2 接缝：两处合并

| 替换什么 | 我们仓库的位置 |
|---|---|
| 经典 CE | `pusch_processor_impl.cpp:264` `estimator.estimate(...)` |
| 经典 eq + demap | `:559` `demodulator.demodulate(...)` |
| ★ 而设备侧**已经是深度 3 的形状** | `merged_hop`（*"the whole hop's buffer"*，一个 CB 覆盖整跳，mkf033 中位 **449.8 µs**） |

### 4.3 引擎：默认 ANE，态度 open

- ★ **默认 ANE**：AI 推理专用引擎；本机实测 **141 µs vs MPS 690 µs**；
  与仓库架构原则 *"AI 推理走 NPU"* 一致；
- **Metal/MPS 为对照臂**，由 P4/P5 实测裁决是否例外；
- ★ **ANE 的真实约束是设计约束**（自定义 Metal kernel 不能进 ANE 图、fp16 量程、工作集悬崖、
  `EnumeratedShapes` 分桶），不是"所以别用"。

### 4.4 执行位置：**内联**，不走外部 dApp

外部 dApp 框架对神经接收机是 **Inexpressible**（没有把 LLR 张量送回同一槽 PUSCH 链的回路），
且会把每槽 MB 级搬运加回一条以"零主机↔设备数据穿越"为核心成就的 lane。

## 5. 范围边界（**不做**的事）

| 不做 | 理由 |
|---|---|
| **不替换 LDPC 译码器** | LLR 是链条接口；译码器保持经典 |
| **不做端到端训练** | 译码器进训练收益 mixed-to-weak（有论文用可微译码器却报告无增益）；进**评测**是必须的 |
| **不重构 CE 线** | AI CE 由 `ai_ce` 独立负责 |
| **不动下行 / 不改帧结构** | 我们是**接收机侧**改动 |
| **不追求"超过经典"作为 P0 之前的目标** | 那是待证伪的假设，不是前提 |
| ★ **不为"零穿越"而拒绝采集** | 穿越是手段不是目的（设计 §0.1.4） |
