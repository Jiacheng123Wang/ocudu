## 2. 增量结论（必读）

1. ★★★ **那 ~450 µs 与"活"无关**（`p84`，判决）：同一条 cb、同一派发网格、同一线程组大小、同一绑定、同一屏障、同一提交，**所有 kernel 换成空 kernel** ⇒ 窗口 **470.0 → 462.9**（−1.5%）。
2. ★★ **结构律（累计七条数据点）**：一跳设备时间合计恒 **~505–517 µs**，其中**恰好一条 cb** 吃 ~450–520，**哪一条随结构搬家**（融合 = `merged_hop`；拆分 = `dft` 445.8；关 D1 = lane burst 459–517），**而它的内容无关** ⇒ 这笔账属于**结构/平台**，不属于算力。
3. ★★ **队列/依赖等待也被同腿否掉**：消去跳的 `commit→start` **203.2 → 44.1 µs**（一跳总账 673 → 507），**`start→end` 却一动不动** ⇒ 不是"排队/等依赖被记进窗口"那一类。
   累计已证否：kernel 算力（`p84`）、设备侧等待（§6.131①）、足迹 537 MB（§6.131②）、队列排空（§6.131③）、绑定大小（§6.131④）、线程组串行（`p77`）、同伴车道（`p76`）、派发价（`p72`–`p74`）。
4. **唯一还站得住但没尺子可证的机制候选**（**记录，不作杠杆**）：那条 cb 的 `start→end` 里含一个**跨队列网格依赖**（前端队列产出 → 后端队列消费），即驱动把"资源就绪"的等待算在这个缓冲的执行区间里。本平台**没有逐派发时间戳**（§6.130③）、**event 只有 cb 粒度可见**（§6.130①）⇒ 不再投入。
5. ★★ **这一族缺陷四次都是"状态放错作用域/次序"**：`p80`（决策点在"新建 cb"分支）、`p81`（`thread_local`）、`p82`（label 被覆盖行盖掉）、本会话（"谁会赢"写成**按次序赋值**）。
   ⇒ **纪律**：凡"谁会赢/谁说了算"的逻辑，写成**表达式或单一归属点**。
6. ★ **消去法的覆盖范围必须逐个 dispatch 问清楚**："旋钮开着"≠"我关心的那段被消去了"。**凡不过 `shared_burst::encoder()` 编码的 dispatch，必须主动来问 `ablate_cb()`**（现已在代码里写明）。
7. ★ **阳性对照要选"旋钮必然覆盖到的总体"**，否则它的"没塌"会被误读成"消去没生效"（`p83` 的教训）；**行为证据（CRC）与窗口证据分开记账**。
8. **`p84` 的其它数字**（将来引用）：`dft_front_end n=364609 exec 46.5`（min 5.5/p5 6.2）、`ce_weights n=145225 exec 40.1`、`late_handed n=2538 exec 50.1`（min 6.2）、busy split `ch_wt 41.1 + merged_hop 477.8`、`lanes=145220`、`released=147752`、`fence wait` median 34.1 µs（**不是**那 ~450 的来源）、`burst dispatches=4.00/跳`。
9. **已知口径**：`dft_front_end`（plain 路）不是融合车道的前端；一跳墙钟 **1935 µs**（换量纲必须用它）；`merged_hop` 的 `commit→start` 在 (B) 修复后是 ~215 µs。
10. ★★ **"92% 是什么"已有答案（§6.144⑤）**：**A = 等本跳最后一个样点 473.0 µs（实测 `[ul_rx_wait]` 中位）** + **车道 cb 的平台账 472.3/lane**（与内容无关＝`p84`）＋ 车道内 **gap 140.0** ＋ **差值得到的 LLR 路径 256.6**（= 1409.8 − 473.0 − 43.4 − 636.8）。⚠ **嵌套，不是相加**（宿主与设备重叠）；**每个数的出处（p86 stderr 行号）已列入 §6.144⑤ 的"依据"表**。
11. ★ **A 有直接读数，不要再说"没仪器"**：`[ul_rx_wait]`（按块、`report()` 无条件打印）——**p86 实测中位 473.0**（§5.8.29 在 cpu 腿上 1057.0）。§6.144⑤ 的树原来标"无直接读数"并用 ≈500 参与运算**已更正**（§6.145⑦）：残差随之从 "~230" 改为 **256.6**。
12. ★★ **上行吞吐的机制（§6.143）**：同时隙数下 n78 **10.70** vs n1 **16.60** Mbit/s ⇒ 剩下的 **1.55× 全是每 RE 的质量**（BLER 50.1% vs 23.1%，4.49 vs 1.57 bit/RE）⇒ **与 GPU 车道无关**，是"功率摊到 51 PRB"的物理账 + TDD 配比。
13. ★ **探针纪律（§6.145③，新规范）**：**两把钥匙**（编译期 option 默认 OFF + 运行期 env 默认关）；**关着 ⇒ 交付路径逐字节不变**；**开着 ⇒ G1/G2 红线必须仍绿**（`crossings` 判 0、`[ul_dft_wait]` 无样本、`[ul_gpu_lane] host` 在噪声内），否则**探针改变了被测对象**、读数不可用。禁止：中途 `waitUntilCompleted` / 中途读回设备数据 / 中途阻塞轮询。
14. ★★★ **那个"每条腿都 ~101 ms"的 `[ul_rx_wait] max` 已归因（§6.146）—— 是本进程自己的启动项，不是打嗝**：`ru_controller_sdr_impl.cpp:70-76` 的 `delay_s = 0.1` 把**电台流的起点**定在 `now + 100 ms` 并对齐到子帧，而接收线程立刻开始要样本 ⇒ **每次运行的第一条 `receive()` 必然等 ~100.5–101.9 ms**。
    **证明**：`slip` 只对"有前驱"的调用计算（`if (last_return_ns != 0)`）⇒ 任何非首次调用满足 `recv ≤ slip_max + air`（p86：8.8 ms + 0.5 ms = 9.3 ms ≪ 100.8 ms）⇒ 那 100.8 ms **只能是首次调用**。跨 **53 条腿 / 3 种模式 / 9 天** `recv_max` 恒在 100.5–101.9 ms，`loop_max` 仅 0.1–7 ms，`rx_overflows` 几乎全 0。
    ⇒ **读法**：`[ul_rx_wait] max` 是**常量**、不要当症状；判打嗝看 `[ul_rx_timing]` 的 `recv/loop/slip` 与 `[ul_rx]` 的 `rx_overflows/gaps`。反例（真积压）只有 `p36-bigframe`（`slip_max 59.7 ms`、`rx_overflows 135143`）。
15. ★ **A 的口径（§6.144⑤ 新增）**：`A = slot − δ`，`δ` = 宿主**发起** `receive()` 的时刻相对槽边界的相位。p86（n78）A 中位 473 ⇒ **δ = +27 µs**；用户引的 n1 腿 A 1054（slot 1000）⇒ **δ = −54 µs**。⇒ **A 变小 ≠ 变快**（样本在槽末之前不存在；跳最早也只能从那里起步），而且 **V1 与 A 同锚在 `Tc`** ⇒ `V1 = 物理延迟 − δ`：跨腿比较必须知道 δ（p86 是 27 µs）。真正的目标是 **`T1 → LLR` 的 936.8 µs**。

## 4. 纪律（本会话又花过代价的）

1. ★★ **"谁会赢/谁说了算"的逻辑一律写成表达式或单一归属点**，不要写"按次序赋值"——这一族已经四次（§2.5）。
2. ★★ **消去法（或任何"减法"测量）飞之前，先列出"这条 cb 里每个 dispatch 由谁编码、谁提交、label 是谁"**，逐条确认旋钮覆盖得到。
3. ★ **阳性对照必须选"旋钮必然覆盖到的总体"**；**行为证据（CRC/数值）与窗口证据分开记账**。
4. ★ **打戳必须在所有提交之后**（先重建后提交 = 戳落在旧提交上）。
5. **腿停了等进程退出**（`[metal_stats]` 是 atexit 打的）；`ctest -L phy` **串行**；腿运行时**不碰 GPU/电台**；一条臂一个变量。
6. **判据重述要留原文**（V3 的做法）；**更正写在开发文档并引用**，不回头改旧 memo。
7. ★ **探针的纪律（§6.145③）**：新探针必须**两把钥匙**（编译期 option 默认 OFF + 运行期 env 默认关）；**关着 ⇒ 交付路径逐字节不变**；**开着 ⇒ G1/G2 红线必须仍绿**（`crossings` 判 0、`[ul_dft_wait]` 无样本、`host` 在噪声内）；**禁止**中途 `waitUntilCompleted` / 中途读回设备数据 / 中途阻塞轮询 —— 否则**探针改变了被测对象**，读数作废。
8. ★ **文档"插入"不要用会全局命中的锚点**：本轮发现 `§6.144⑤` 那 45 行被**逐字插进三处**（`#### ⑤ 结论与下一步` 在文中有三处 ⇒ 锚点替换把所有位置都插了）。凡插入前先 `grep -c` 锚点**必须 = 1**，插完再 `grep -c` 新标题**也必须 = 1**。
9. ★★ **变异/复原之后必须确认"真的重编了"**：用 `cp` 复原被变异的头文件后，`cmake --build` 可能因 **mtime 打平而跳过重编**，于是"复原后仍然 FAIL"——读到的是**上一个二进制**的读数。做法：核对 `Building CXX object` 的**条数**（`=0` 即判该臂 VOID），必要时 `rm -f <obj>` 强制重编。与"旋钮没传进去"（`p78`）、"label 没生效"（`p82`）**同族**。
10. ★★ **"检查存在"≠"检查在判据读的那条路径上"**（本仓第三次同类）：`ul_pipeline_probe_test` 的 8 个用例只挂了目录标签 `support`，而验收跑的是 `ctest -L phy` ⇒ 探针的契约与回归臂**从未被执行**（§6.148⑤）。已加 `phy` 标签；⚠ `gtest_discover_tests(... PROPERTIES LABELS "a;b")` 的分号必须**转义**（否则变成两个属性，`ctest --show-only=json-v1` 可见），且改 CMake 后**必须重新 configure**。验收计数 **193 → 201**。
11. ★★ **门禁里的"总数"要写成下界，不能写成等号**：审计要求 `ctest -L phy` 恰好 `out of 193`，而 §6.148⑤ 让标签涨到 201 ⇒ **第一次合法增长被读成 FAIL**。已改成 **100% 且 n ≥ 193**（缩水照样抓——那正是探针 8 个用例掉出验收路径的方式）。
13. ★★ **电台会"边缘化"且能自愈**（2026-09-28 首次遇到）：`p92` 第一次（11:56）与 `p94`（12:08）都出现 `exceeded maximum number of timed out receive calls`（~104 s 接收静默）⇒ 后者以 `uhd::usb_error … LIBUSB_ERROR_NOT_FOUND` 未捕获异常 **Abort trap: 6** 收场，那条腿无报告、已作废；夹在中间的 `p92` 重跑与 `p93` 却完全干净。
    ⇒ **纪律**：① 任何 abort / 强杀 / `Forcing exit` 之后**先给 B200 断电重启**并 `uhd_find_devices` 确认；② 每条腿**头 15 s 看 stdout**，出现 `exceeded maximum` / `failed receiving packet` 就立刻 Ctrl-C（那条腿必 void），别盲跑完。
12. ★ **读 `[ul_slot_trace]` 的第一件事是数"完整行"**：`ldpc` 非 NaN ⇔ 该行是**该周期**的一次真实跳；空载腿 512 行里可能只有十几行完整（`p89` 15 行），这**不是异常**而是"重置"语义的正常形态（分布序列不受影响）。`probe_recheck.sh` 会直接打这个计数。
