# 困难样本捞取计划（hard-sample harvest）—— 提高 LDPC 迭代上限以获取 7–20 次迭代的 ground truth

> **一句话**：把 dump 回放的 LDPC 迭代上限从 **6 提到 20**（一个环境变量），
> **原本 `crc=KO` 的单元里会有一些变成 `crc=OK`** ⇒ 它们就带上了 ground truth，
> 而且 `iterations` 字段如实记录 **7–20** ⇒ **正是"悬崖临界点"的训练样本**。
>
> 版本：v1.0（2026-11-26，香港）｜ 状态：**待试点**（阶段 A 未跑）
> ｜ 适用语料：`w2`、`s2_mcs`、`s2_amc`（三套母集都已带 `iterations` 口径）

---

## 1. 动机

| 事实 | 数值 |
|---|---|
| 现有母集的临界样本（`iterations ≥ 4`）占比 | **s2-amc 30.2%**、**w2 26.0%**、**s2-mcs 15.8%** |
| 但 `iterations` 的**上限就是 6**（活链配置） | `du_low_config.h` 默认 **6** |
| ⇒ 现有语料**无法提供**"6 次解不出、20 次能解出"的那一档 | ★ **这一档恰恰是最难的** |

**⇒ 所以"向困难样本倾斜"目前只到 `iterations=6` 为止；再往难的一档，语料里根本没有。**

## 2. 机制（已用源码确认）

```cpp
// lib/phy/upper/channel_processors/metal/test/ul_chain_replay.cpp
unsigned replay_dec_nof_iterations() {
  unsigned iterations = 6;                                     // 与空口一致
  if (const char* env = std::getenv("OCUDU_REPLAY_DEC_ITERATIONS"))
      iterations = static_cast<unsigned>(std::strtoul(env, nullptr, 10));
  return iterations;
}
```

| 项 | 结论 |
|---|---|
| ★ **开关** | ★ **环境变量 `OCUDU_REPLAY_DEC_ITERATIONS=20`**，**不改代码、不重编译** |
| ★ 判定会变 | ★ 源码注释原话：*"a reception the decoder would crack on its seventh iteration is `crc=KO` at a cap of six and `crc=OK` at ten"* |
| ★ 迭代数如实记录 | ★ `index.csv` 的 `iterations` 列写**实际次数** ⇒ **7–20 会被记录** |
| ★ 标签来源 | ★ 这些单元**被成功解出** ⇒ **TB 比特就是 ground truth**（与现有样本同源、同质量） |
| ★ 独立性 | ★ 只改回放侧的 cap，**不动空中链路、不动现有母集、不动模型** |

## 3. 什么算"捞到的困难样本"

| 单元在原 dump（cap=6）| 在 cap=20 的 dump | ★ 归类 |
|---|---|---|
| `crc=OK`，`iterations ≤ 6` | `crc=OK`（同） | 已有样本（不新增）|
| ★ `crc=KO` | ★ **`crc=OK`，`7 ≤ iterations ≤ 20`** | ★ **困难样本：新增训练样本** |
| `crc=KO` | `crc=KO`（20 次也不行）| ★ **仍无标签** ⇒ 只保留在评测集（全腿测试用）|

**⇒ 新增样本的 `iterations` 天然就是"难度标签"，抽训练集时可直接按它加权/分层。**

| ★ 母集体积增长 | 新增样本约 = KO 数 × 命中率 × 单样本体积 | ★ 预计 **+5–15 GB/套**（远小于现有 154–332 GB）|

## 12. ★★★★★★★ 2026-11-26 17:35 **更正：`iterations` 是**各 codeblock 的均值**，不是"这个 TB 需要多少次"——所以"cap=6 KO 却显示 4 次"不是 bug**

**(a) ★★ 用户提出的逻辑质疑（成立）**

> 若一个单元在 cap=6 下 KO、却在 cap=20 下报 `iterations=3..6`，那原 dump 就有问题——它没把 ≤6 次能解出的样本找出来。

**(b) ★★★ 实测澄清：那个 TB 有 **5 个 codeblock**

| cap | `on_sch` | 输出行 |
|---|---|---|
| **6** | ★ `crc=0`（TB 失败）| ★ `crc=KO iterations=4` |
| **7** | ★ `crc=1`（TB 成功）| ★ `crc=OK iterations=5` |

```
geometry: tbs=4612 B (36896 bits), bg=1, 5 codeblock(s) reserved
```

**⇒ 5 个 CB 里**最差的那个需要 7 次**；cap=6 时它失败 ⇒ TB 判 KO（**原 dump 正确**）。**

**(c) ★★★ `iterations` 是**均值**（源码位置）**

```cpp
// ul_chain_replay.cpp
nof_iters = sch.data.ldpc_decoder_stats.get_nof_observations() != 0
                ? sch.data.ldpc_decoder_stats.get_mean() : 0.0F;
```

且 `pusch_decoder_result.h` 明写：*"the **average** number of iterations for correctly decoded codeblocks"*。

**⇒ 所以"4"完全可以是"4 个 CB 各 3 次 ＋ 1 个 CB 需 7 次"的均值 ⇒ **均值不能用来判断"是否在 6 次内能解出"**。**

**(d) ★★ 因此计划的两点修订**

| 项 | 修订 |
|---|---|
| ★ 1 | ★ **难度标签用 `hard=1`**（cap6 KO → cap20 OK），**不**用 `iterations` 判难度 |
| ★ 2 | ★ **新增 `iterations_max` 字段**：replay 的统计对象本身就有 `get_max()` ⇒ 把"最差 codeblock 的迭代数"也输出，母集可存两列（均值 ＋ 最大值）|

**(e) ★ `iterations_max` 的实现范围**

| 层 | 改动 |
|---|---|
| `ul_chain_replay.cpp` | 输出行加 `iterations_max=%u`；`OCUDU_REPLAY_CSV` 加一列 |
| `dump_tb.sh` | 解析并写入 `index.csv` 的新列 |
| `build_depth3_dataset.py` | 母集里新增 `iterations_max.npy`（与 `iterations.npy` 并列）|
| 兼容性 | ★ 旧索引没有该列 ⇒ 取 `-1`（未知），与 `iterations` 的口径一致 |

**(b) ★★ OK 名单的来源（唯一权威）**

| 来源 | 路径 |
|---|---|
| ★ **已归档的原 tb dump** | ★ `s2_<kind>_tb_tarballs/tb_<腿>.tar.gz` 里的 **`index.csv`** |

**(c) ★★ 提取策略（两种单元，两种代价）**

| 单元类别 | 需要什么 | 为什么 |
|---|---|---|
| ★ **候选**（rv0，原 KO）| ★ **4 个文件**（`.txt/.bin/_h.bin/_ce.txt`）| ★ 要重放 |
| ★ **供体**（rv≠0，可被合并）| ★ **4 个文件** | ★ `--harq-chain` 要读它的采样 |

**(d) ★ 为什么这对 harq 群体是**必须**的**

★ `harq_backfill.py` 的链式归属要看到**整条腿的 PDU 序列**（rv0 开链、rv≠0 归属、按 (rnti,harq) 与短间隔判定）。

## 19. ★★★★★★★ 2026-11-26 21:25 **困难样本天然偏向高调制——本腿 99.7% 是 256QAM，这是物理结果而不是漏做**

**(a) ★★ 一个容易被误判为 bug 的现象**

`s2_amc_ping_1123z` 的困难样本集只有 **256QAM（7 935）＋ 64QAM（6）＋ QPSK（17）**，16QAM 为 0。
第一次只建了 256QAM，看起来像"漏了其它调制"——实际是**候选本来就集中在一个调制**。

**(b) ★ 为什么（机理）**

| 环节 | 事实 |
|---|---|
| ★ 候选 = 原 dump 的 `crc=no` | ★ 即**经典链解不出**的单元 |
| ★ 解不出集中在哪里 | ★ **高调制/高码率**（256QAM）|
| ★ QPSK 几乎全解出 | ★ 母集 `QPSK_self` 只有 **36** 个样本 ⇒ **没有失败，就没有可捞的困难样本** |
| ★ 反证 | ★ 母集 64QAM/256QAM 样本量大（13 798 / 19 194）⇒ 失败多 |

**⇒ 所以"困难样本集偏向高调制"是**难度分布的直接投影**，不是工具缺陷。**

**(c) ★ 对抽训练集的影响（重要）**

★ 若按**调制配额**均分抽集，`_hard` 群体（99.7% 256QAM）会被稀释掉 ⇒ **违背"向困难样本倾斜"的初衷**。
★ **正确做法：把 `_hard` 当作独立的难度层**，按 `iterations_max` / `hard` 分层加权，**不与常规母集按调制混配**。
