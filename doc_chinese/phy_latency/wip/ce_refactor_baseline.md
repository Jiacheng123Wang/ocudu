## 3. ★ 一跳的账（§6.191–§6.196 更正后的版本）

**kernel → cb 的对应**（读码定死，**不是**按阶段名相加 —— 纪律 45）：

| kernel | 离线价 µs | 在哪条 cb |
|---|---|---|
| DFT 14 变换（1 派发 × 14 线程组）| 47.3 | `merged_hop` |
| CE 抽取/LSE 段（`apply_lse` 7.5 + `pilots_*` ≈3）| ≈10 | `merged_hop` |
| eq 1.9 + demap 1.4 | 3.3 | `merged_hop` |
| CE 相关段（`corr_a` 1.7 + `corr_r_hp` 6.0 + inv/apply）| ≈9 | `ce_weights` |
| CE 权重（`mmse_weights` 13.2 + `reformat` 1.4）| ≈14.6 | `ce_weights` |
| **合计** | **≈84** | `merged_hop` ≈61 / `ce_weights` ≈24 |

⇒ `merged_hop` 窗口 **469.1** vs 它的 kernel **≈61** ⇒ **≈408 µs 未归属**；`ce_weights` **41.5 vs ≈24** ⇒ **自洽**。
⇒ 三条**互不依赖**的读数同时指向同一空洞（它是"这条 cb 的价钱"，不是任何 kernel）：
① **消去法**（`p84`，全空 kernel、同网格/同线程组/同绑定）窗口 470.0 → **462.9**（−1.5%）；
② **四条结构各有一条 ~450–520 µs 的 cb**（融合 = `merged_hop` 469；拆分 = `split_dft` 443.5；关 D1 = lane burst 516.7；消去 = 462.9）；
③ **同腿排除**：栅栏 Q24 只 16.6 µs/跳、设备占空比 Q9-F3 只 **16.7%**、`dl_tx_slack` 已证明运输健康。
⇒ ⚠ **不要再把"`iq2ce − busy`"读成宿主账**（§6.167②）；**也不要把不同序列的中位数相加**（纪律 44）。

## 5. 改动 CE 之后怎么用这份 baseline

1. **必须再飞一条同配方的 `pNNN-n78-*`**（`OCUDU_METAL_GPU_TIME=1` + `OCUDU_UL_PHASE_SEGMENTS=1`、`--regime=default`）；
2. **先过 §0 的可用性前置门**（`AT/BELOW 0 == 0`、`slip >1ms ≈ 0`、`PDUSession ≠ 0`）——不过就别读时延；
3. 再核 `paired iq2ce` 样本数与本节 17672 同量级（否则总体不可比）；
4. 判据顺序：**契约 9/9 → `stale=0` → V1 中位不退化 → `iq2ce`/`ce` 段是否下降 → `merged_hop` exec p50 是否下降**；
5. ★ 方向 A（缓存 A/A⁻¹/R_hp/W）**预期省 4 个站点 ≈5 次派发/跳** ⇒ 若它有效，**`ce` 段（64.8 µs）与 `ce_weights`（41.5 µs）应当先动**；`merged_hop` 若**不动**，那正好再次印证 §3（窗口与内容无关）；
6. ★ **自检**：`paired iq2eqdem` 应始终 **= V1**（±0.5%）。若不等，先查探针而不是查 CE。
