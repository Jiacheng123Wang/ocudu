# S3 — A/B：宿主不再读提取的标量（`OCUDU_CE_HOST_SCALARS`）

**提交**：`861a4feeb3`（已推送）
**改动**：`port_channel_estimator_metal_mmse_impl.cpp` —— 新增 `host_reads_device_scalars()`
（`OCUDU_CE_HOST_SCALARS`，**默认不变**），并给四处设备标量读取加守卫。
**类别**：A 类（A/B 旋钮，默认关 ⇒ 默认路径不变）。**判据 = 开关两条腿发布数据逐字节比较。**

**⚠ 本步没有把穿越次数降下来（仍是 3.00/跳）。它造出了尺子，并给出了一个决定性的结论。**

---

## 1. 假设与做法

**假设**：那三次回读算出来的东西，**对 GPU 已经是死的**——
核在 `sigma2_from_device` 置位时不读 `p.sigma2`（`ocudu_mmse_corr.metal:151`），
而 `OCUDU_CE_K0A_RATIO_DEV` 默认开；CFO 也已由设备在 K4 自读（`2eca4a7965`）。

**做法**：`OCUDU_CE_HOST_SCALARS=0` 时宿主**不读**、并把值置为**确定的 0**
（**不是未初始化的读**——否则运行不确定，dump 对比就失去意义）。

## 3. 分界线是几何，而且与块大小**完全吻合**

`pusch_channel_estimator_mmse_block_prb` 默认 **3**（`du_low_config.h:121`，范围 1..3）：

- **PRB 是 3 的倍数 ⇒ 没有余数 ⇒ 设备建全部相关矩阵**；
- **否则有余数 ⇒ 并进 edge 块 ⇒ 那个块保留宿主建**
  （代码原话：*"the edge group keeps the host build and staging below"*）。

语料分得**干干净净**：

| 捕获 | PRB | 结果 |
|---|---|---|
| `syn001_3` `syn002_3` `syn003_3` `syn007_6` `syn008_6` `syn009_6` `syn016_12` `syn017_12` `syn018_12` `syn022_18` `syn023_18` `syn024_18` | 3,6,12,18（**3 的倍数**）| **逐字节相同** ⇒ 宿主的标量**对 GPU 是死的** |
| `syn004_4` `syn005_4` `syn006_4` `syn010_8` `syn011_8` `syn012_8` `syn013_10` `syn014_10` `syn015_10` `syn019_14` `syn020_14` `syn021_14` `syn025_25` `syn026_25` `syn027_25` | 4,8,10,14,25（**有余数**）| `_h`/`_llr` 改变 ⇒ 它们**真的在给 A 装对角** |

**⇒ 被推翻的不是方向，是捷径**：**穿越不能靠删掉读取来消除**，因为这些形态里约 15/27 仍在消费它。

## 4. `_ce.txt` 的差异是另一件事（必须分开说）

它差的是**头部的上报统计量**：`noise_variance`、`snr`、`cfo_hz`。
**读取确实喂它们**，但**它们不属于 IQ → LLR 链**——那是**旁路输出**。
⇒ "拿这些统计量怎么办"是**自己的一个问题**，不是核的依赖。**不要把它和 A 的对角混为一谈。**

## 5. 对 S4 的影响（**形状已明确**）

1. **前置件就是 §48.194(g-sesvicies) 说的那件事**：把 K0-d 的覆盖扩到**合并 edge 块**。
   **在那之前，穿越 3.00 降不下去。**
2. **本 A/B 就是 S4 的判据**：K0-d 覆盖补完之后再跑它，应当**在每个形态上都是 0 字节差异**。
   这把"补覆盖"从一个愿望变成了一个可执行的检查。
3. 统计量（`noise_variance`/`snr`/`cfo_hz`）单独处理：设备侧计算 / 降频回读 / 或明确接受。
