## 2. 增量结论（必读；★ = 会改变你判断的）

1. ★★ **P2-E（`OCUDU_DFT_RELEASE_TOKENS_EARLY`）不吃尾巴**：它在**分裂模式里根本不作用**（交棒被拒、`by_event=0`），在融合车道里**保持默认开**，但理由改成"**去掉输入保持**"（`by_event` 25–33%）；§6.156 的"60–70×"**已撤回**（§6.157）。
2. ★★ **ms 级接收尾巴的定位**：**结构性易感在 GPU 路径**（模式统计 + 同会话对照）；**直接症状位置 = 宿主↔电台接口**（双向同时、比值 1.3–1.6；`grid_devwaited=0`、`loop>1ms` 0–2 次、池绿 ⇒ 不是池/网格/我们的等待/我们的 RX 宿主代码）；**触发条件未知**（欠账）。**它不是速率/期限代价**：每跳宿主占用只有 ~710–780 µs，跳到达 **431/495/281 跳/s** ⇒ **占用率 20–39%**，`stale` 2/0/1 ⇒ **零期限错过**；"上行更晚更抖 ⇒ OLLA/RACH ⇒ 小 TB"这条链**已撤回**（`p130` PHR +7..8 vs `p131` +11..12 ⇒ 归链路）。
3. ★ **D1（交棒）机制**（§6.160）：前端把"装满未提交"的 cb 交给车道（`release_block()` → `shared_burst::adopt()` → 车道一次提交；`grid_ready` + registry 保证宿主读者顺序；无人采纳由清扫线程兜底 `late_handed`）。**关掉它** ⇒ 每槽一次宿主阻塞（`[ul_dft_wait]` 中位 **147.8**、p95 415.7）⇒ **V1 中位 +~100 µs**（D1 开 10 腿 1354.3–1431.4；D1 关 2 腿 1513.2/1519.1）；**代价只是时延**（占用率与期限都不吃紧）。
4. ★ **`t2f` 的 2× 是"排队等开工"，不是 FFT 分两批**：设备侧 exec 从不翻倍（`late_handed` 48.4/50.0/51.0、plain 路 46.1/46.5/48.1、`merged_hop` 428.7/470.2/491.0；`t2f` 的 2× 落在 `commit→GPU start` 的等待上）；`p131` 复现了"收包后 ~55 µs"。
5. ★ **突发/抖动假设否**（§6.160⑦）：到达不风暴（中位 3 跳/5 ms、最坏 8–9；容量 ≈12.9–14.1 跳/5 ms）；**密度↔时延相关为负**（−0.392/−0.351）；`t=` >8 ms 的跳 0/1。
6. ★ **GPU 冷启动否**（§6.160⑨）：新表 8 条最慢执行 **`idle_before` 全 ≤0.10 ms**、7/8 在忙段；本腿最长 GPU 空洞 2674 ms 之后是 **plain/PRACH 路**。
7. ★★ **470 µs 复查（§6.161②，最重要的方法学发现）**：`p84`"全空 kernel 只掉 1.5% ⇒ 与内容无关"有三个红旗 —— **(1) 覆盖度从未计数**（代码里没有"已消去派发"计数器）；**(2) 阳性对照读在 `dft_front_end` 这个别的标签上**（总体论证，不是逐 cb 证明）；**(3) 量级不自洽**（前端自己那条 cb 掉了数十 µs，含同一批变换的 `merged_hop` 只掉 **7.1 µs**）⇒ **`§6.141`"无杠杆"应撤回/重判**。
8. ★ **对账（§6.161⑤）**：一跳 = `merged_hop` **470.5 µs**（1 cb，含**前端批派发 1.32 + 车道 burst 4.00 ⇒ ≈5.3 个派发**）+ `ce_weights` **43.3**（1 cb）；**`eq_demap`/`ch_est` 的 `cbs/lane=0.00` ⇒ 均衡/解映射就在 `merged_hop` 里**；`4.00` 与 `5.09`（`ce_sites` 的内核站点）**单位不同**；栅栏 `resolved=100%`、共驻留 33%/mean 50.7 µs ⇒ **不阻塞，≈17 µs/跳**。
9. ⚠ **合成离线臂是负结果（§6.161⑦）**：空 cb **0.1 µs**（**无"每 cb 地板"** ⇒ **C-A 死的**）、线程组不影响窗口、事件/跨队列等待编码≈免费、**派发间 RAW 依赖免费**、有界竞争与实时页输入**都不撑长窗口**；但"空 2.75 / 访存 26 µs"这些**绝对单价不可用作离线同类对照**（跨运行波动 3.4×、缓冲只有几百 KB ⇒ 物理上 µs 级）⇒ **合成路已到头**，只剩 **A（真 kernel 按族离线）** 与 **B（按阶段空口消去）**。

## 4. 纪律（本会话新增 21–26；1–20 见上一份 memo）

21. ★★ **一条腿的低尾不是旋钮的读数**：预登记只约束"怎么判"，**不保证判得动**；单腿 A/B 必须先证明两腿在**独立通道**上同档（本会话 = DL 侧 `dl_tx_call`），否则差值归**腿**不归旋钮（§6.157）。
22. ★★ **"某段变慢 ⇒ 协议层后果"这类链条，写进结论前先做时间预算**：**占用率 vs 到达间隔 + 期限读数**，而且**按真实到达过程**算（平均值不够 —— 这正是用户抓到的漏洞，§6.160⑥⑦）。
23. ★★ **消去/减法测量必须有"按标签的覆盖度计数器"**，阳性对照必须读**同一条 cb / 同一标签**；"读码认为覆盖到了"不算（§6.161②，`p84` 的教训）。
24. ★ **合成离线臂在拿来与空口比之前，先证明它在规模/几何上可比**（否则只能当**类别级**证据）：本会话的"访存型"臂其实只有几百 KB（物理 µs 级），跨运行还波动 3.4×（§6.161⑦）。
25. ★ **腿的收尾与报告口径**：**先停流量发生器 → 等上行排空 → 单次 Ctrl-C**；出现 `Could not stop application after 5 seconds. Forcing exit.` ⇒ 报告**被截断**，按纪律作废，但**已打印的前半段可用**，引用时必须写明**缺哪一段**（`p131`/`p132`#1）。
26. ★ **引用"某条 cb 的窗口"必须带口径**：`GPUStartTime→GPUEndTime` 是**墙钟**（含别人插进来的工作），与"执行"、"等待"是三件事；`[ul_gpu_lane] busy/residency`、`merged_hop exec`、`[ul_dft_wait]` 不能混着比（§6.159⑧/§6.161⑤）。
