# macOS 调度机制微基准（P4 的依据）

**为什么要这一组**：2026-09-01 有一次"给所有 RT worker 自动加 1 ms Mach 时间约束 + 跳过
`pthread_setschedparam`"的改动，随后 **OAI-UE 随机接入回归**（Msg2/RAR 正常，卡在 Msg3 contention
resolution）。当时两件事一起回退，**从未归因到具体哪一件**。在把 P4（时间约束）重新提上桌之前，
必须先把"时间约束到底值多少、它的哪种参数形状有害"用**可以直接跑的微基准**问清楚——真腿太贵，
而且一次只能回答一个问题。

**这些实验的共同形状**：一个周期性线程用 `mach_wait_until()` 按固定周期醒来，记录
`实际唤醒时刻 - 时限`（µs，越小越好；这就是"运行稳定性"里 `max` 的那一类量），在
**16 个纯 spinner / 14 逻辑核（10 P + 4 E）** 的 2× 超订下测，因为要测的正是"别人抢 CPU 时
我们还能不能准时"。每臂都新建线程（线程的调度档位是**每线程**的，所以同进程内顺序跑各臂是干净的），
每臂都**回读**实际生效的档位（`qos=` / `tc=SET|unset(...)` / `posix=`），确保臂就是它声称的那样。

## 跑法

```sh
bash run_all.sh          # 约 3 分钟，需要机器基本空闲（先确认 pgrep -x gnb 为空）
```

## 结论（2026-10-01 实测，全部在 Apple M4 Pro / macOS 上）

### A. 唤醒延迟：时间约束 ≫ SCHED_FIFO ≫ QoS ≈ 无（`02`、`07`）

16 spinner / 14 核抢占下，500 µs 周期唤醒 8000 次，单位 µs：

| 档位 | p50 | p99 | p99.9 | **max** |
|---|---|---|---|---|
| 无（DEFAULT）| 102.9 | 386.1 | 2932.5 | **5358.1** |
| QoS `USER_INTERACTIVE` | 103.1 | 663.8 | 2272.3 | **3274.0** |
| **`SCHED_FIFO` prio 46**（历史臂的有效制度）| 58.5 | 63.7 | 69.7 | **91.2** |
| **Mach 时间约束 1000/100/200**（2026-09-01 臂）| **3.2** | 6.3 | 7.5 | **9.9** |
| FIFO 46 → 时间约束（两者并存）| 3.2 | 5.6 | 6.5 | **8.2** |

* **时间约束把尾延迟降 700×**（5358 → 9.9 µs），且**所有分位数一起降**（符合"只许 `max` 降"的方向）；
* **QoS 档对唤醒延迟基本无用**：p50 不动（102.9 → 103.1），p99 反而变差，max 只降 1.6×。
  它是**类别提示**，不是**预算预留**。⇒ 本线围绕 `USER_INTERACTIVE` 做的那部分（§10.16 的
  194.65 → 179.12 ivcsw/ms）在这条指标上**没有收益**；
* `SCHED_FIFO` 是**真实优先级层**（尾很紧，max 91 µs，而不是 QoS 的 3274），但它的 p50 有 58 µs ——
  那是**定时器合并**（timer coalescing）的代价：FIFO 不取消合并，时间约束会（它按 deadline 调度）。
* 注：约束之后再调 `pthread_setschedparam`，回读仍是 `posix=OTHER/31` —— 即**显式调度制度是黏的**，
  反过来覆盖不回去（`01` 里另一个方向：约束之后再 `set_qos` 直接 EPERM）。

### B. 互斥是**双向**的（`01`，权威回读用 `thread_policy_get(..., get_default=FALSE)`）

| 顺序 | 结果 |
|---|---|
| `set_qos(UI)` → `thread_policy_set(TC)` | `set_qos` 成功（qos=33），**TC 之后 qos=0** ⇒ 约束**抹掉**档位 |
| `thread_policy_set(TC)` → `set_qos(UI)` | `set_qos` 返回 **1 (EPERM)**，档位停在 0 ⇒ **不给** |
| 历史形状 `24000/24000/24000` ticks（= 1 ms，24 MHz 时基）| 内核**照收**，同样把 qos 清 0 |

⇒ **Darwin 规则（补完）**：线程要么 QoS 管理，要么显式调度（POSIX 参数 **或** Mach 时间约束），
**永不两者兼具**；显式调度**不可逆**。所以 P4 的代价就是 **QoS 档本身**——这不是历史回归的附带
损伤，而是**必然**。而由 A 可知，**这个代价换来的东西更值**。

### C. 参数形状：只有一种有害（`04`、`05`、`06`、`03`）

同样 16 spinner，每周期做真实的活儿，测"申报的 computation"与实际用量的关系：

| 形状 | wait p50 | wait max | 超期 |
|---|---|---|---|
| 无约束，150 µs 活儿 / 500 µs 周期 | 871 087 | 1 891 652 | 大量 |
| **TC `1000/1000/1000`（历史原版形状）** | **4.9** | **12.1** | 0 |
| TC `1000/200/400`（标定值）| 4.4 | 11.2 | 0 |
| **TC `1000/1000/400`（`constraint < computation`）** | **792.8** | **7 277** | 多 |
| TC 申报 1000 µs、实际每周期用 4600 µs（**持续超额 4.6×**）| **3.2** | **9.7** | **0** |
| TC 申报 1000 µs、每 100 周期一次 3 ms 突发（仍在 5 ms 周期内）| 3.8 | 16.0 | **0** |
| TC 申报 1000 µs、实际每周期只用 20 µs 额度却用 150 µs（少报 7.5×）| **75 366** | 128 110 | 多 |

* **`computation` 不是硬上限**，只是预留声明：持续超额 4.6×、突发 3× 都**不被惩罚**，约束照常满效；
* **唯一有害的形状是 `constraint < computation`**（畸形请求）：p50 迟到 793 µs、max 7.3 ms。
  历史原版的 `1000/1000/1000` **不属此列**（三者相等，合法）；
* 唯一另一个坏例子是**申报的额度小到荒谬**（20 µs 报 150 µs 的活儿）：中位罚停 75 ms。
  这不是"标定不准"，而是**申报了 4% 占空却要 30%** 的量级错误。

⇒ **结论：2026-09-01 的参数形状无罪。** 这一条直接推翻了"当年是 100% 占空把机器抢死了"的猜测。

### D. 同层之间的次序（`08`，弱信号，仅作方向参考）

12 个 hog 线程全部是 TC（= 真实 gNB 里所有 worker 都是 TC 的情形），测一个线程 A 的唤醒延迟：

| hog 参数 | A 参数 | p50 | max |
|---|---|---|---|
| 无 TC | `1000/100/200` | 16.0 | 130.8 |
| `5000/1000/4000`（松）| `500/50/100`（**紧，差异化**）| 14.5 | **78.7** |
| `500/50/100`（紧）| `500/50/100`（**同参，并列**）| 15.3 | 86.4 |
| `5000/1000/4000`（松）| `5000/1000/4000`（**同参，并列**）| 19.0 | **571.8** |

主因是 **A 自己申报的绝对紧度**，不是"与别人是否差异化"；差异化在同参对撞（571.8）时看起来有帮助
（78.7），但样本只有一组，**不作为结论**，只支持一条设计规则：**逐线程按自己的真实预算申报，不要
给所有线程发同一个 1 ms**。

### E. 一个被记录在案的方法学错误（`09_ARTIFACT_*`）

`09` 曾经"测出"突发之后有 2.02 ms 的惩罚。**那是算术假象**：突发 3 ms 超出了 1 ms 的周期，
`mach_wait_until(next)` 的死期**早已过期**，于是 `now - next` 自然等于超出量。修法是让突发**仍在
周期之内**（`05`：周期 5 ms、突发 3 ms），此时**零惩罚**。留档的理由：这个错误的方向恰好会
"证实"我们当时想信的假设（内核惩罚突发），**只有反向检查（把突发塞进周期里）才暴露它**。

## 对 P4 的直接含义

1. **机制是真的**：时间约束是这台机器上唯一能"向内核预留 CPU"从而**免疫外部干扰**的手段
   （§10.28 收口结论里"优先级改不动 `max`"指的是 **QoS 档**；时间约束**改得动**，且幅度是 700×）；
2. **代价（丢 QoS 档）是划算的**：QoS 在这条指标上本来就没有收益（A 表）；
3. **参数规则**：`period` = 线程自己的循环周期；`constraint ≥ computation`（**硬性**）；
   `computation` ≥ 该线程实测每周期 CPU 的 p99.9（留余量）——由 C 可知**报大不报小**；
4. **逐线程、可开关、可回退**：不能像 2026-09-01 那样一次性给所有 worker 发同样的参数。
