# depth4 —— 神经网络 LDPC 解码：公开文献调研

★ 版本：2026-10-21（初稿，10 篇原文已下载至 `../ref_paper/`）

## 0. 先写清楚"我们在哪"

depth3 网络的输出是**软比特（LLR）**，之后进入经典 LDPC 解码器：

| 事实 | 值/位置 |
|---|---|
| 码 | 5G NR LDPC，BG1/BG2，lifting Z ≤ 384，码块 n 最大 26 112 bit |
| 解码器 | `ldpc_decoder`，**offset min-sum**，**layered** 调度，迭代 3–6（实测 `iterations=3` 常见） |
| 时延预算 | 单次接收的 `deliver` ≈ 100 µs 量级；解码在 CPU/GPU 上，**没有 ANE 的位置** |
| 已有标签 | 训练集里每个单元都带 `bits`/`tb_bits`（传输比特与 TB 比特）⇒ **监督信号现成** |
| 已有额外信息 | depth3 的 head 2 给出**逐 RE 的噪声方差** ⇒ 每个 LLR 的**可靠性**已知 |

★★ **由此得到本次调研的第一条约束**：**任何"每一步迭代都跑一次神经网络"的方案，在实时性与功耗上都不成立**。
可行的方向是"**学参数 / 学调度 / 学停止**"，让神经网络**训练时**出力、**推理时**不出现在关键路径上。

## 1. 文献地图（按方法族）

| 族 | 代表工作 | 机制 | 对我们 |
|---|---|---|---|
| **A. 学习型 BP（NBP）** | Nachmani 2016/2018 | 给 Tanner 图的**每条边**一个可学习权重，展开固定迭代次数，端到端训练 | 增益来自"打破 BP 的对称性与短环影响"；但**参数按边数增长**，5G NR 长码边数 ~10⁵，需结构化共享 |
| **B. 参数化 min-sum** | Lugosch 2017 | 把 min-sum 的 **offset / 归一化因子**变成可学习参数（按迭代、按度数） | ★ **最贴合我们**：解码器就是 min-sum 家族，参数几十个，推理**零额外延迟** |
| **C. 超图/GNN 解码** | Nachmani 2019 | 把解码写成图网络，允许越出 BP 的不动点 | 表达力强，代价是每迭代一次前向 |
| **D. Transformer 解码** | Choukroun 2022（ECCT）、CrossMPT 2024 | 把码字与校验矩阵（或其掩码）作为序列输入，注意力建模 | 短码强；**注意力 O(n²)**，n=26 112 时 ≈6.8×10⁸ ⇒ 不可行 |
| **E. 学"图/结构"** | 2406.12900 | 学的不是消息权重而是**因子图本身的边/度分布** | 与 NBP 互补；对"码设计"有价值，对"给定 5G 码"价值有限 |
| **F. 率兼容 / 多任务** | 2310.06256 | 一个网络覆盖多码率、多打孔图样 | 对 **IR-HARQ（rv 变化）** 有直接意义，我们的空中数据 rv 恒为 0 ⇒ 先记下 |
| **G. 噪声猜测（非神经）** | Duffy 2019（GRAND） | 不译码而**猜噪声**：按似然顺序枚举差错图样，查码本 | 范式参照；混合路线=用网络给候选排序；对短码/低码率有竞争力 |
| **H. 基础模型** | ICLR 2024 | 跨码族通用解码器，预训练 + 适配 | 训练成本与实时性都不适合嵌入式 RAN |

## 2. 关键判断（针对我们的系统）

### 2.1 最有价值的一条：**参数化 min-sum**

理由：
- 我们的解码器**已经是 offset min-sum**；把 `offset`（以及归一化因子）从常数换成
  **按 (迭代层, 校验节点度数/变量节点度数) 分组**的可学习参数，**参数总量几十个**；
- 推理时这些参数是常数 ⇒ **没有额外时延**，也不需要 ANE；实现上就是查表；
- 训练便宜：可以用现有捕获 + 标签，端到端对 **BLER** 或 **BCE of 译码后比特** 求梯度；
- 风险低：可随时退回经典 offset（把参数设回原值）。

★ 这是**唯一能在当前实时预算内落地**的路线，建议作为 R1。

### 2.2 第二条：**学调度与停止**（文献薄弱，但我们收益最直接）

我们的解码是 layered，迭代 3–6 次；每次迭代的**层顺序**与**提前停止准则**都是经典启发式：
- 层顺序影响收敛速度 ⇒ 可以学一个**固定顺序**（离线搜索，不需神经网络）或**按 syndrome 自适应**；
- 提前停止：现在是"奇偶校验全过 或 迭代上限" ⇒ 可以学"**再迭代一次是否值得**"的分类器（输入：syndrome weight、迭代数、LLR 幅度统计）。

★ 收益是**吞吐/时延**而不是 BLER ⇒ 与我们已有的 `iterations=3` 观测直接相关，容易量化。

### 2.3 第三条：**把 depth3 的可靠性喂进解码器**

NBP 的权重本质是"消息可信度"；而我们已经**逐 RE 知道噪声方差**（head 2），
⇒ 可以把"LLR 可靠性"作为 NBP 的**初始权重**或作为参数化 min-sum 的**分组依据**（高噪声 RE 的边权重更小）。
★ 这是 depth3 与 depth4 的**天然接口**，也是别人没有的输入。

### 2.4 明确不做的

| 方案 | 不做的理由 |
|---|---|
| Transformer 全码块解码（ECCT/CrossMPT） | O(n²)，26 112 bit 不可行；且需要 ANE/GPU 在关键路径 |
| 基础模型（ICLR 2024） | 训练与推理成本、需要多码族数据 |
| 每迭代一次 NN 前向（NBP/GNN 原样） | 时延与功耗不成立（除非参数量极小、编译成查表 —— 那本质回到 2.1） |
| 直接替代解码器（端到端学译码） | 只在短码成立；我们的 TB 可达 26 kbit，且 CRC 之外无误码保护 |

## 3. 数据与监督（我们现成的东西）

| 监督信号 | 来源 | 用途 |
|---|---|---|
| 传输比特（`tb_bits`/`bits`） | 训练集标签 ✓ | 监督 BCE / BLER 目标 |
| **syndrome weight** | 解码器中间量 | **无监督**目标（文献常用）：不需要标签，可用**线上数据** |
| CRC 结果 | 解码后 | 二值反馈，可做 RL/拒绝采样 |
| depth3 的逐 RE 噪声 | head 2 | 边权重先验 |

★ 注意：**syndrome 目标**让我们能用**未标注的现场捕获**训练 ⇒ 数据量不成问题。

## 4. 评估口径（必须先定，否则数字不可比）

1. **BLER vs SNR**（每码块），以及**误块率在 1e-2 / 1e-3** 的 SNR 差；
2. **平均迭代数**（我们的 3–6 是关键成本）；
3. **单次解码时延**（CPU 上的 µs 级），以及**是否有额外前向**；
4. **与经典 offset min-sum 的逐块一致性**（回归测试用）。

## 5. 结论与建议路线（按风险从低到高）

| 路线 | 内容 | 风险 | 预期收益 | 建议 |
|---|---|---|---|---|
| **R1** | **参数化 min-sum**（学 offset/归一化/分组，几十参数，零推理开销） | 低 | 小到中（文献里短码 0.1–0.5 dB 量级，长码待测） | ★ **先做** |
| **R2** | **学调度 + 提前停止**（分类器/查表，输入 syndrome 与 LLR 统计） | 低 | 吞吐/时延（迭代数下降） | 与 R1 并行 |
| **R3** | **NBP 结构化加权**（按边类型/度数共享，输入含 depth3 的噪声） | 中 | 中（需要更重的训练与验证） | R1 之后再评估 |
| **R4** | **GRAND 混合**（网络给噪声候选排序，仅用于小码块/SRB） | 中高 | 小码块上可能显著 | 观察 |
| — | Transformer / 基础模型 / 端到端替代 | 高 | 上限高但不可落地 | **不做** |

## 6. 下一步（讨论用）

1. 先量**基线**：现有解码器在同一批捕获上的 BLER、平均迭代数、时延 ⇒ 没有基线无法判断任何改进；
2. 用 R1 做**最小可行实验**：只学 2–4 个参数（每迭代一个 offset），看 BLER 与迭代数是否变化；
3. R2 的**停止准则**可以完全离线做（不需要神经网络）：先验证"提前停止"能省多少迭代；
4. 训练/推理的**接口**：解码器在 `lib/phy/upper/channel_coding/ldpc/`，需要确认可注入参数的粒度（见待读清单）。
