## 1. 最终目标（代码原文）

`include/ocudu/phy/phy_pipeline_mode.h`：

> **`gpu` — fused lane.** 整条 **IQ → LLR** 链跑在**一条设备侧流水线**里，只有**两次**
> host ↔ device **数据**穿越（**IQ 上传**、**LLR 下载**）。车道接管它包含的模块的后端；
> **LDPC 解码器不属于车道**（LLR 仍然要离开设备去 CPU 解码）。

而这条线的**排序标准**（README §2 纪律 1 + 交接长期有效）：

> **判据是"穿越次数"，不是微秒。** 排序标准是**功能正确前提下 CPU 还剩几个参与点**，不是收益。
> 任何"这不值 X µs"的论证在本线一律无效。

**⇒ 目标可以拆成两半**：**数据面**（两次穿越）与**控制面**（CPU 中途不再参与：整条链**一次**提交）。
延迟是副产品，但**是** P3 的实际代价，所以必须带预算判读。

### 2.3 延迟面 —— **P3 为什么没翻默认**

| 读数 | P2 腿（`event`，当前默认）| P3 腿（`merged`）| 来源 |
|---|---|---|---|
| `[ul_gpu_pipeline]` mean / median | **2103.5 / 1993.1 µs** | 3666.2 µs（median）| §5.8.8 / §5.8.10 |
| 后端 GPU 工作/跳 | **470.3 µs**（`ch_wt` 394.5 = 84%）| 704.5 µs | §5.8.11 |
| 该跳内失去的重叠 | — | 只有 ~69 µs | §5.8.11 |
| 两条腿的 **min** | 1357.1 µs | 1355.7 µs | §5.8.11 |

**已查清的三件事**（都是测量，不是推测）：

1. **宿主不是瓶颈**（两次独立证伪）：估计器宿主侧全部工作 **16.3–17.7 µs/跳**，却要等 GPU **665–887 µs**；
   前端栅栏开着也无效（`signals=26371 waits=31660`，延迟没变）⇒ §5.8.11 结论 1、§5.8.12 结论 1。
2. **P3 的代价是"提交粒度"，不是"宿主重叠"**：两条腿的 **min 几乎相同**而中位差 1.65 ms，
   本跳内失去的重叠只有 69 µs ⇒ 合并把"两次可重叠的提交"变成"一次更大的提交"，
   在**突发上行**下排队更久。**⚠ 这个差被负载混淆**（两条腿 regime 不同），要同负载口径才能定论（§5.8.11 结论 2）。
3. **延迟的大头不在这一跳自己的 GPU 工作里**：后端每跳只用 470 µs，而**最快**的一跳也要 1355 µs（2.9×）
   ⇒ 差额是**流水线结构**：DFT（前端 ~420 µs/槽）→ 栅栏 → 估计器 → 权重 → 均衡 → 解映射 → LLR 回读 这一串**串行**边界与排队（§5.8.11 结论 3）。

**接收后那 ~1 ms 的分解**（§5.8.12，空中）：**DFT ~40% / 权重链 ~40% / 均衡+回读 ~15% / 交接 4%**。

## 3. 差距（还差什么）

| # | 差距 | 量 | 性质 |
|---|---|---|---|
| **A** | **提交数 2.00 → 1.00** | 每跳少一次 CPU 提交 + 一次栅栏 | **目标本身**；P3 已实现并验过，**只需翻默认** |
| **B** | **让 A 可负担：每跳 GPU 工作** | `ch_wt` 627 µs + DFT ~420 µs | 设计文档原话："**把每跳 GPU 工作砍下去，1.00 才可负担**"（§5.8.13 末、§5.8.11） |
| **C** | **P4 收尾** | — | 退役 escape hatch、清理 `if (!st.burst) barrier` 那族假定、把 probe 的 lane 定义改回一跳一条（§5.8.2）|
| **D1** | **DFT 还不在车道里**（目标性差距）| 每槽一次 CPU 提交（空中 `dft commits=27412`，~249/s）| `ocudu_metal_lane_probe.h` 原文：per-symbol DFTs "are **not part of the lane yet** … they are also **the stage that moves onto the lane's queue when the fused pipeline lands**"。⇒ 严格按"**整条** IQ→LLR 链跑在**一条**设备侧流水线里"，这一跳未达成 |
| **D2** | **DFT 从未被离线量过** | 空中 ~40%，~420 µs/槽 | 它是链条**最前面**、且属多模式共用的 `ocudu_dft_metal_engine`（§5.8.12）|
| **E** | **P3 的延迟代价没有干净口径** | +1650 µs（被负载混淆）| 翻默认之前**必须**补一条同负载 A/B（§5.8.11）|

> ## ★ 2026-09-20 收盘补充（§5.8.18）：**靶子的性质变了**
>
> 把导频抽取（162.7 µs）逐 dispatch 拆开之后：**96% 的 171 µs 落在四个「1 个线程 ~ 1 个线程组」的
> dispatch 上**，而**唯一并行良好的那个（LSE，全 grid）只要 1.5 µs（0.9%）**。
> 其中 `mmse_pilots_cfo` **是单线程内核**（72.8 µs），而代码注释写明它**必须**是：
> 它的答案是一次 **72 项 atan2 串行累加**，**那个累加的编译形态本身就决定发布位**
> （批 5g 实测：重编译 ⇒ CFO 移 1 ulp ⇒ 翻转发布网格的单精度值）。
>
> **⇒ 被量到的三大项 K1 197.5 + 抽取 171.3 + 重排 116.9 = 485.7 µs = 空口 `ch_wt` 的 75%，
> 贵的都不是算术量，而是「低并行度的串行」，而那个串行次序就是发布位。**
> 能并行的已经并行完了 ⇒ **剩下的不是「优化哪个 kernel」，而是「要不要保留逐字节契约」的裁定。**

**⇒ 一句话：目标的两半，数据面已经达成；控制面的【机制】也已达成并空中验过（P3 = 1.00），
剩下的是"把 P3 接成默认" + DFT 搬进车道（D1）+ P4 收尾；而"接默认"被延迟挡着，
延迟的两大块是 DFT 与权重链，权重链的内部现在第一次有了逐段账单。**

> **⚠ 一处必须说清的口径**："延迟太大所以没接默认"方向对，但**那 +1650 µs 不干净**——
> 两条腿的 **min 几乎相同**（1355.7 vs 1357.1 µs），只有中位差 1.65 ms，且本跳内失去的重叠只有 ~69 µs。
> 干净的说法是"**合并成一次更大的提交后在突发上行下排队更久**"，不是"流水线本身慢了"。
> 而且这仍是**假设**（负载混淆）⇒ 翻默认前必须补同负载 A/B（差距 E）。
>
> **⚠ 另一处**："优化 GPU 延迟"是**手段**——排序标准仍是**参与点**；而且**每跳 GPU 工作不是延迟的主导项**
> （后端 470 µs/跳 vs 最快的一跳 1355 µs）⇒ "砍 `ch_wt` ⇒ 延迟同步下降"**不能线性外推**，
> 它只在"那一段恰好在关键路径上"+"排队惩罚随提交变小"时成立，后者目前是假设。

## 4. 规划

### 4.1 总路线（不变，§5.8.2 的三条纪律）

* 每个阶段**只动一种提交**，头条数字各自独立；
* 每阶段的离线判据是**逐字节不变**（27 语料 + 20 窄捕获 = 235 dump）+ 提交数；
* 每阶段有**独立回滚路径**；腿过就 `git tag -a` 并推送，不过就回滚到上一个 tag；
* 空中判据四条：**契约 8/8、穿越 0.00+0.00、RF failure 0、CRC 不劣化**，外加该阶段的头条数字。

### 4.2 下一步（按证据强度，全部**离线**，不需要 sudo / 不需要 OTA）

| 步 | 做什么 | 为什么是它 | 判据 |
|---|---|---|---|
| **1** | **把导频抽取（162.7 µs，26%）逐 kernel 拆开**：`mmse_pilots_lse` / `cfo` / `sigma2` / `power` / `epre` | **第二大项，且从未被优化过**；`lse` 是逐元素的（§19.6.3：可以加算术），`cfo`/`sigma2`/`power` 是**长累加/归约**（要当心）| 先用现成臂（`CPU_LS=1`、`DEV_SIGMA2=0`、`DEV_TA=0`）+ 保值性复验，得出每 kernel 的斜率 |
| **2** | **把重排（116.9，其中 TA 80.1）拆细** | 第三大项；§18.7 那条"把 TA 移出关键路径"的实验**现在有了价码** | `REFORMAT_REPEAT=2` / `DEV_TA=0`；TA fence 实验按 §18.7 的做法 |
| **3** | **量 DFT 的离线分段**（~420 µs/槽，空中 ~40%，**从没离线量过**）| 它在链条**最前面**，它的时间直接进延迟；两套工具（`--repeat 1` 协议 + 隔离台架）现在都有了 | 分段 + 保值性；注意它属**多模式共用**的引擎 ⇒ 改动面更大 |
| **4** | **★ 裁定：逐字节契约（它现在覆盖 `ch_wt` 的 75%）** | K1 微调已全部量掉（§5.8.16）；抽取 96% 在四个低并行 dispatch 上、`cfo` 是**按契约必须单线程**（§5.8.18）；重排未拆但同族 | **用户裁定**：放开契约 = 允许换算法/换归约树 ⇒ 判据变成"重定基线 + 一条 OTA 按 CRC/契约判"。**先离线估收益再决定** |
| **5** | **把 P3（`merged`）翻成默认** | 这是**目标性**的那一步；前四步把每跳 GPU 工作砍下去之后才可负担 | 离线：逐字节不变（已 ✅）+ 提交数 1.00；空中：四条标准 **+ 同负载口径的延迟 A/B**（差距 E）|
| **6** | **P4 收尾** | 把 escape hatch 退役、把 probe 的 lane 定义改回一跳一条 | 只跑回归 |

### 4.3 每一步的"停手"条件

* 离线判据**任何一条不过** ⇒ 不进下一步，先修（教训：P5 因为数值错整块回退，§5.8.13）；
* 空中腿**任何一条标准不过** ⇒ 回滚到上一个 tag，问题必在本阶段新增的那一步（§5.8.2）；
* **RF failure ≠ 0 的腿不算腿**（磁盘上全部腿的规律：RTF=0 ⇒ CRC ≥ 85%；RTF ≥ 200 ⇒ CRC ≈ 30%）。

## 5. 已知的坑与不确定性（诚实清单）

### 5.1 已经量掉的（别再试）

1. **K1 的微调**：几何（默认已最优，最好的替代 1.1%）、barrier 数（2→1 反而更慢；K1b 少 9 倍却贵 2.1 倍）、
   算术量（n^1.27）、并行度（`nof_systems` 1→8 **成本一动不动**）——见 §5.8.16。
2. **逐 dispatch 计数器仪器**：这台设备**不可能**（只有 `AtStageBoundary` 一个采样点，compute 编码器上直接 SIGABRT）——§5.8.15 ①。
3. **"让宿主重叠下一槽"**：宿主每跳只有 ~16 µs 的活，这条路线最多藏住 ~100 µs，而中位延迟 2000–3700 µs——§5.8.11 结论 1。
4. **前端栅栏**：开着无效（假设已证伪）——§5.8.12 结论 1。

### 5.2 工具/口径的坑

5. **离线 `busy split` 必须按协议读**：`--repeat 1`、一个进程一跳、N≥9 取**中位数**；
   `--repeat 20` 是**双峰**（12 次里 3 次低 45%）。**用 `corpus/syn027_25`（25 PRB = 空口几何）**，不要用 4 PRB 的——§5.8.15 ③、§5.8.16 ①。
6. **报旋钮臂之前先在代码里确认旋钮名字存在**：`OCUDU_CE_DEV_INVERT` **不存在**（真名 `OCUDU_CE_GPU_INVERT`/`CPU_INVERT`），
   拼错的旋钮是**静默空操作**，读数看起来像"这段不花钱"——§5.8.17 ④。
7. **`OCUDU_CE_DEV_Y=0` 不是外科臂**（连设备 rSRP/TA 一起关）；**`OCUDU_CE_INV_REPEAT` 只在奇数下数据可用**；
   **`OCUDU_CE_INVERT_FIRST=1` 现在产出 NaN**（禁用）——§5.8.15 ⑤⑥、§5.8.17 ④。
8. **空中 `busy split` 跨腿不稳**（上午 383 µs、下午 564 µs，kernel 完全相同）⇒ 空中 A/B 要**同负载成对**——§5.8.15、交接开放项 12。
9. **上腿之前关掉手机的 WiFi**（手机开 WiFi 会自己拆蜂窝会话）；**判读前先看 `Real-time failures` 是否为 0**——`wip/S14_phone_drops.md`。

### 5.3 还没回答的（这些是第 1–4 步要回答的）

10. **导频抽取 / 重排 / DFT 是否真有【逐位保值】的余量**？——三块都没被优化过，本会话只量出了它们的价格。
11. **K1 换算法能降到多少**？（Newton–Schulz 之类；高度并行、barrier 极少，但舍入不同）
12. **P3 的同负载延迟代价到底是多少**？（差距 E）
