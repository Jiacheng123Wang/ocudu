### 1.3 时延实测（2026-10-26，`ab_timing.py`，252 子载波桶）

**先纠正一个口径**：`estimate` 段不是"CPU 经典估计器"，而是 **Metal MMSE 估计器**——`--metal` 把
`port_channel_estimator_algorithm::metal_mmse` 装进接收机，也就是 **fused Metal PHY pipeline 的信道估计段**。
它只在**回退开启**时跑（`OCUDU_DEPTH3_FALLBACK` 默认开），**纯 AI 模式下为 0**。

**两种模式的差别（E4，同一条捕获，`--repeat 700`）**：

| 段 | 回退开（默认）| **纯 AI（`OCUDU_DEPTH3_FALLBACK=0`）** |
|---|---|---|
| `plane` p50 | 175 | **29** |
| **`forward` p50** | 834 | **282** |
| `forward` max | 2 687 | **2 706** |
| **`predict` p50**（ANE）| 735 | **267** |
| `estimate` p50（**Metal MMSE**）| 1 539 | **0** |
| `deliver` p50 | 3 754 | **1 003** |
| `deliver` max | 7 625 | 4 284 |

**⇒ 部署用的是纯 AI 模式，所以门④ 只能按纯 AI 记**；回退开的数字（3.8 ms）是**另一种配置**，不能混用。

**纯 AI 下的结构对照**（同捕获，各取 3 次里最好的一次）：

| 模型 | 参数 | `forward` p50 | `forward` max | `predict` p50 | `deliver` p50 |
|---|---|---|---|---|---|
| **E4** | 26 185 | **282** | **2 706** | 267 | 1 003 |
| **E10** | 11 001 | **241** | **2 696** | 225 | 1 024 |

**读数**：

1. **ANE 单次 ≈ 225–267 µs**，与设计假设的"~400 µs"同量级（更小）。
2. **参数少 58% 只快 15%**（282 → 241）⇒ ANE 在这个尺寸上**不是算力受限** ⇒ "缩结构换时延"论据不成立（§19.568）。
3. **max 两者都 ≈2.7 ms，是 p50 的 10 倍** ⇒ **尾部不是参数决定的**，而是主机/调度抖动
   ⇒ **门④ 的 Max 列会长期是瓶颈**，它比 p50 更该盯。
4. `deliver` p50 ≈ 1.0 ms 是**回放的主机端到端**，不是空口时延。

### 1.4 门② 的两种口径：★ Python 85.9% ✓ vs ★ C++ **67.9%** ✗

同一批 attach 语料，两种实现给出**差 18 pp** 的结果。**以 C++ 为准**，因为那才是部署链。

| 侧 | 实现 | 总体 | 256QAM × ≤4 |

| Python | `gate_e17.py` ＋ Keras ＋ 25→6 迭代 | 85.9%（n=9 217） | ~64% |

**逐格（C++，整条 attach 腿 6 430 / 6 456 条）**：

| 格子 | n | CRC-OK |
|---|---|---|
| 256QAM × ≤4 | 3 386 | **42.0%** |
| 256QAM × 5–8 | 105 | **57.1%** |
| 64QAM × 5–8 | 2 222 | 97.8% |
| QPSK × ≤4 | 324 | 100.0% |
| QPSK × 9–24 | 320 | 99.7% |

**为什么不能用 Python 的数**：三处偏差都朝**同一个方向**（见 §19.578）：

1. Keras float32 vs Core ML **fp16**；
2. Python 解码 **25 迭代** vs 空口 **6**（单这一项在验收集上是 −3.2 pp，§19.579）；
3. **桶截断**：Python 喂整张 612 平面，部署对窄授权用**最小的 108 子载波桶**。

**差得"不均匀"比差多少更重要**：QPSK 几乎不掉、64QAM×5–8 只掉一点、256QAM×≤4 掉 22 pp
⇒ 若是 fp16 精度问题，各格应**均匀**下降；实际是窄格被毁、宽格几乎不受影响
⇒ **主因是分布不匹配（桶截断），不是精度**（§19.587）。

**修法（待定）**：① 训练时也按桶宽裁平面；② 窄授权改走更宽的桶（时延上升）。

## 2. 每一代的来龙去脉

### 2.1 E1 → E2：换语料

同一结构（2 头、18 blk、c32），E1 用**旧语料**、E2 用**新语料**。E2 的符号一致反而
更低（98.54 vs 99.01）⇒ **"新"不等于"好"**，这一对当年没有定论。

### 2.2 E3：合成窄样本

为了修 attach（5–8 PRB）而加入**合成的 2 PRB** 样本（39 662 条）。结果：**分箱在中段
略退化**（+0.05…0.22 pp）。后来（§19.449）用合成 2 PRB 验证集重测发现它**在 2 PRB 上
每一档都更好**（10 dB 处 −8.8%）——但**现场产生不了 2 PRB**（调度器下限 4 PRB）⇒
**收益用不上，代价是真的** ⇒ 不采纳。

### 2.3 E4：当前的默认

**真实语料 43 902 条**、2 头、18 blk、c32、26 185 参数。三门里最好的一代：
符号 **99.93%**、attach **27/40**、分箱全过。

它在空中实链上的表现（2026-10-24）：goodput **8.26**、重传 −18%、延迟中位 355/760 µs
（与 c32h 同）⇒ **默认模型**，部署在 `depth3_e4_real_1023/`。

### 2.4 E5：加数据

把 59 k 合并语料喂进去。分箱最差 **+0.15 pp**，正好**卡在阈值上** ⇒ 不采纳。
**这一代的价值是证否**：语料**规模**不是瓶颈（E5 之后的所有改进都来自**形状**）。

### 2.5 E8：四个头

在 E5 语料上把测量头从 2 个加到 4 个（`ch_est`、`dmrs_noise` 回来）。判据记录是
"中性偏负"（分箱略差），具体数字未以可引用形式留存 ⇒ **不采纳**。**报告类头不如共享测量层**（后者让 E4 的 goodput
从 7.56 升到 8.26，+9.3%）。

### 2.6 c32h：共享测量层

与 E4 **同一批权重**，但把 `ch_est`／`dmrs_noise` 去掉、改由共享层测平面。
goodput **7.56 → 8.26（+9.3%）**、重传 **−18%** ⇒ **这是 E4 相对 c32h 的全部收益来源**，
也是"测量路径比语料更重要"的直接证据（§19.4xx）。

（分箱相对 E4，因语料不同**不可直接比**；**轨内**互比才有效。）

### 2.8 E9：按调制配比重建语料

把语料按 **45/30/15/10** 的调制配比重采样，总量 27 k。结果：**分箱反而更好**（+0.09，
低 SNR 加权起作用）但 **attach 崩到 13/30** ✗。

**原因（§19.461）**：调制配额把**窄授权**顺带削掉了（43.2% → 29.5%），因为窄授权以
QPSK 为主。**教训：配额必须是多维的。**

### 2.9 E15：三维分层

把 E9 的错纠正：按 **(调制 × 宽度 × SNR)** 分层，总量 60 k，低 SNR 全取。
结果 **attach 回到 26/30** ✓ —— 与 E9 的 13/30 形成**干净对照**，**正面证实**了宽度
被削是 attach 崩掉的原因。

**遗留**：符号一致 **98.62%**，与 E9 **完全相同**（两位小数）⇒ 说明它与语料无关，
是训练侧或某个共同维度的问题；分箱 **+0.15 pp** 卡在阈值上。

### 2.10 E16：同一语料，换选点方式

E16 与 E15 **同语料、同结构**，只把选点从"低带 BER 早停"换成"验证损失、跑满 40"。

| | E15（band/8）| **E16（val/0）** |
|---|---|---|
| 符号 | 98.62% ✗ | **98.28% ✗**（更差）|
| attach | 26/30 ✓ | **27/30 ✓** |
| 分箱 | ✗ +0.15 | **✓ +0.13** |

**⇒ 结论：选点方式不是符号一致偏低的原因**（换掉它反而更差），**原因在语料** ✓。

**而这指向一个更重要的问题**：门① 的 98.7% 阈值是在**旧语料**（低 SNR 占 ~12%）上定的；
新语料低 SNR 占 **16.5%**，而低 SNR 的 LLR 符号本来就更容易错 ⇒ **这个门控阈值对低 SNR
更重的语料可能定得不合适**。E4 的 99.93% 是在**低 SNR 样本很少**的语料上量的。

**⇒ 待办**：用"按 SNR 分层的符号一致率"重新审这个门，而不是一个总数。

### 2.11 E13 / E14：同一结构，两种语料

| | E13（旧语料）| E14（E9 语料）|
|---|---|---|
| 结构 | c24 / 8 blk / 7 545 | **同** |
| 符号 | **98.57% ✗** | **97.23% ✗** |
| attach | **15/30 ✗** | **10/30 ✗** |
| 分箱 | ✗ +0.49 | ✗ +0.27 |

**⇒ 这是唯一一对"只差语料"的对照**，但它**没有信息量** ✗：两个模型都在门限之下很远
（attach 15/30 与 10/30，门限 20/30），差异落在"都不可用"的区间里，**不能归因于语料**。

**⇒ 结论**：`b8` 太浅（A 轨的判据已指向 ≥12），**在这个结构上做语料对照不成立**；
"只差语料"的对照要在**能过门的结构**上做（E15 vs E9 是这一类，但两者结构相同语料不同，
E15 已证明三维分层把 attach 从 13/30 救到 26/30）。

### 2.12 E10 / E11：E9 语料上的两个缩减

> **E12 补记**（2026-10-26）：E12 是同一批里的 `c24/b18`，已完成（21 epoch，best val 0.09915）。在新验收集
> （E17，3 294 条、每格 50）上：**码块级 CRC-OK 72.9%**、**传输块级 72.5%**，而 **E4 是 80.9% / 79.0%**
> ⇒ **低 6.5 pp**。三个 E9 语料模型（E9 13/30、E11 13/30、E10 13/30、E12 也落在同一档）指向同一结论：
> **E9 语料是主因，结构不是**。

| | E9（c32/b18）| E11（c32/b12）| **E10（c24/b12）** |
|---|---|---|---|
| 参数 | 26 185 | 17 737 | **11 001** |
| 符号 | 98.62% ✗ | 98.17% ✗ | **97.12% ✗** |
| attach | 13/30 ✗ | 13/30 ✗ | **13/30 ✗** |
| 分箱 | ✓ +0.09 | ✓ +0.10 | ✗ +0.19 |

**⇒ 三个模型在 E9 语料上**都过不了 attach**（都是 13/30）** ⇒ 差异不在结构，**在语料**。
**⇒ 因此 E10 不能用来判 c24/b12 是否可行**：它和 E9、E11 站在同一条已被证否的语料上。

**⇒ 要判 c24，必须在 E15 语料（三维分层）上跑 c24**：E19。
