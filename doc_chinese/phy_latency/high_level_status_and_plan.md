## 0. 一句话现状

`gpu` 融合车道的端到端时延（重上行、中位 **≈2675 µs**）**每一项都已归位**：
约 473 µs 等本槽样点 + 48 µs 前端主机 + **901 µs 等单车道空出来** + **1125 µs 本跳设备执行** + 110 µs Pass-3；
而接收缓冲的**持有期 = 这个跨度**，池只有 **8 个 × 每槽 1 个** ⇒ **≈4 ms 就把池抽干**，
接收线程被 `pop_blocking()` 阻塞、电台 underflow（`gpu` 476–733 次 vs 同负载 `cpu` 0–1 次，3/3 条腿复现）。

**进度**：P0 仪表**全部完成并且已在空口收口**（P0-6 生效并发度 / P0-1 分组 GPU 时间 / **P0-5 探针配对**——
腿 `p05-pair` 上配对**精确相等**：73529 == 73529，零丢失；`p0_gate.sh` 10/10 PASS）；
P1-8（车道并发度 1→2）**已实测并两次复现**：`ce` 3228 → ~51 µs、跨度 −55%，
**但代价是同一改动压出一次 ~5 秒收包停顿（两次复现）⇒ 只能算测量结论，不能交付**；
**P2-E（输入缓冲寿命解耦）机制已实现，但被平台证伪**（macOS 26.6.2 只在命令缓冲完成时发布"中途"事件信号），
**待用户裁决**（§5）。**P2-F（并发度作为交付）也必须用户二次裁决**。

⚠ **P0-5 的配对读数同时作废了两个被当作"事实"的比例**（开发文档 §6.3 ⑥）：
"residency 里 ~95% 是 busy" 只对 **n78 加压腿**成立（0.93），**n1 默认腿是 0.643**；
"`eq_demap` ≈ residency" 在两条腿上都**不是**恒等式（都 ≈ **1.09 ×** residency）。
⇒ 引用 D 项（本跳设备执行）时必须写清**哪条腿的 busy**：n1 的一跳设备执行是 **517 µs（中位）**，不是 1125。

## 1. 目标与验收判据（**先写死，不随结果改**）

| # | 判据 | 阈值 |
|---|---|---|
| **V1** | `[ul_gpu_pipeline]` 中位跨度 | **≤ 2150 µs**（重载基线 2675 µs，−20%）|
| **V2** | 症状消失：接收池 | `starved_events == 0` 且 `held_max < pool`（池 = 8）|
| **V3** | 电台 | RF 失败 **≤ 10**（cpu 量级 0–1）、`gaps == 0` |
| **V4** | **不许用提交数换时延** | `cbs/lane ≤ 2.00 (max=2)`、`dropped == 0`（用户裁决：**只约束交付**，测量臂放行）|
| **V5** | 不回归 | 契约 8/8、`crossings 0.00+0.00`/跳、CRC KO% 不劣化 |

**验收腿 = 加压配方**（n78，`iperf3 -c <phone> -R -b 40M -P 4 -t 240`，`--regime=stress`）。
**默认工况**（n1 + 接入 + 标准流量）判契约 8/8 与 `stale=0`。两种配方的完整写法、以及
"判据有三个绑定维度（工况 / 流量 / 几何）"的纪律见开发文档 §3.2/§3.3/§5。

## 3. 下一步

### 3.1 等用户裁决的（我无法单方面决定）

1. **P2-E 怎么走**（开发文档 §6.4.4 的选项表）：建议**保留开关（默认关）作仪器**，然后二选一——
   **接受 +1 提交**把前端块做成独立提交（V4 需重新裁决），或转 **P2-D**（用 P0-5 的配对分布按持有期定池容量）。
2. **P2-F（并发度作为交付）**：§7.5 的杠杆已实测，但必须先查清那次 **5 秒停顿**（§4 Q9）才会有交付形态。
3. **两条陈旧网**（§4 Q11）：`value_net` 的归档基线是否重建；`ab_dumps` arm1 是否曾经绿过。

### 3.2 可以立刻做的（不需要裁决）

1. **飞一条 n1 + 并发 2 的腿，判 Q9**（仪器已就位，开发文档 §6.7）：读 `pop_blocking wait (P0-2`（max / `over 1s=`）、
   `input hold (P0-2`（max 与**最久持有的 slot**）、`paired/phase account`。判读先写死：
   `wait max ≈ 5 s` 且 `hold max` 也是秒级 ⇒ 链条闭合；`wait` 只有 ms 级 ⇒ 5 s 不在池→收包链上，回到电台/驱动侧。
   ⚠ 下一条腿也顺带恢复"腿跑的是哪个提交"这条证据（P0-2 是代码改动，`p05-pair` 已不再是 HEAD 的证据）。
2. **查那次 ~5 秒停顿**（最大未决项 Q9，开发文档 §6.6 已把链条坐实到"池空 → 收包阻塞 → 电台丢样点"）：
   缺的一环是"**为什么两条车道在飞时被持有的块 5 秒不完成**"（并发 1 同样 EMPTY，代价却是 ms 级）。
   ⇒ 下一步是**实现 P0-2**（token 持有期直方图 + `pop_blocking` 等待时长 + 最久持有的 slot/stage），
   一次并发 2 的腿就能判"5 s 是否就是持有期"。
   ⚠ 它是**代码**改动 ⇒ 会让 `p05-pair` 的提交证据失效；**与 Q13 的配对账输出一起、一次改一次飞**。
3. **P1-6**（`OCUDU_UL_SLOT_TRACE` 逐槽时间线）把 B 项（48 µs）拆开，并补 `ce` 尾部的残余归因。
4. **P2-D 的输入已经齐了**：P0-5 的配对分布给出了 n1 的真实持有期分母
   （`residency` 835.5 / `busy` 515.9，配对样本 73529）——如果 P2-E 走不通，这是最便宜的一条。
5. ~~下一次动代码时的两件小事（配对账输出 + 访问器）~~ ✅ **已随 P0-2 一起做完**（开发文档 §6.7）。

**P0-5 的腿已经飞过（`p05-pair`）**，无需再飞：`p0_gate.sh p05-pair` → **10/10 PASS**，读数见开发文档 §6.3 ⑥。

## 4. 未决问题（状态一览；细节与出处见开发文档 §8）

| Q2 | `ce` 的 p95 尾巴（1782 µs）来源 | 基本收口（单车道排队 + 上一跳缓冲回收）；两者各占多少待 P1-6 |

| Q5 | residency 里的 busy 是必要工作还是低效执行？ | 开放，依赖 Q1。⚠ **"~95% busy" 已作废**：n1 配对后 0.643、n78 0.93，逐腿读 |
| Q6 | 并发度能否吃掉 `ce` 的排队项？代价？ | ✅ 能（−58~64×）；代价 = 5 秒停顿（两次复现）|

| **Q9** | **那次 ~5 秒收包停顿的成因** | **已收窄，仍开放**（开发文档 §6.6）：链条 = 池被未完成的块按满 → `pop_blocking` 按住接收线程 **5.002 s** → 电台溢出丢样点；**只有并发 2 付出 5 s**（并发 1 同样 EMPTY，代价 ms 级）。缺的一环 = "被持有的块为什么 5 s 不完成"；判别靠 **P0-2**（持有期直方图 + 池等待时长）|
| Q10 | n1 2.85 倍退化是否还有 `ce` 之外的成分 | 主因已定位；`p05-pair` 配对后 `ce` = 3278 µs = 跨度的 **62%**，设备执行只有 517 µs |
| Q11 | 两条"改前就红"的网怎么处理 | **待用户裁决** |
| Q12 | `s84b-p0` 第一次尝试没有日志（最可能被"戳 ≠ HEAD"拒绝）| 登记（低优先，**未验证**）：要它作证据就得重飞；否则按无效腿处理 |
| Q13 | 配对账里 **199 行（0.2%）** 既没匹配也没淘汰（被同 slot 的后一条车道覆盖）| 低优先；与 Q14 的自解释输出一起做 |
| Q14 | 一跳的设备执行在 n1 上是多少？ | ✅ **已收口（P0-5 配对）**：**`busy` = 517 µs（中位）**，不是 residency 836、也不是 n78 的 1125 |

### n1 默认腿 2.85 倍退化（已定位，2026-09-24/25）

| 腿 | 小区 | `[ul_pipeline]` 中位 | 池 `starved_takes` |
|---|---|---|---|
| `s47/s49/s51`、`s61/s62` | n1（`origin/main` 合并前）| **1844–1896 µs** | 1–39 |
| `s83-tag` / `s84-p0` | **n1（合并后）** | **5263 / 5260 µs** | 696 / 1192 |

单变量腿定死主因：**并发 1 时 `ce` = 3228 µs；并发 2 时 `ce` = ~51 µs、跨度 5268 → 2400/2359**（两次复现）
⇒ **是"等串行 strand"，不是 GPU 算力、不是收样点**。⚠ 但同一条改动也两次复现了那次 **~5 秒收包停顿**（Q9）。

## 6. 与里程碑的关系 / 不做的事

* 本工作流**不是**"契约变红"：契约 8/8、crossings `0.00+0.00`、就地装配在**所有重载腿上仍成立**；
  它针对的是"**车道在高负载下给电台添麻烦**"——里程碑之后的新工作项。
* **不做**：用额外提交换时延（V4）；用更大的池冒充时延改善（那是诊断 P1-4）；改预登记判据去迁就某条腿。
