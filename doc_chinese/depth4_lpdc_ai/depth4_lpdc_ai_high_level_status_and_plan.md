# depth4（把 LDPC 解码纳入网络）—— 高层现状与规划

> **一句话**：depth3 的输出是**软比特**，交给经典 LDPC 解码器；depth4 把这条链**再延伸一段深度** ——
> **一个 Core ML 模型**：输入是 depth3 的同一张平面（＋ 常量），模型内完成
> **主干 → 码字装配 → 16 层消息传递 → 硬判 → 解扰**，输出**解码后的 TB 比特**（另有 `soft` 输出供训练）；
> **中间没有"给经典解码器的 LLR"这个接口**；**CRC 与 FAPI 封装在 host**（那里本来就要回到 CPU）。
> **部署形态只有一种：B-CoreML**（整张图一次调用）；**不做早退**。
>

## 4. 高层架构

```
输入：平面(612×14×(12+4)) ＋ 常量（Qm/层数/scaling/RNTI/n_ID/rv/TBS/分配）
  └─ depth3 主干（CE/EQ/DEMOD，18 块 c32，26 k 参数）        [模型内]
       └─ 码字装配（解匹配/解交织，固定置换，零参数）          [模型内]
            └─ 16 层消息传递（基图稠密化，标量/LUT 消息函数）  [模型内]
                 ├─ soft（每 TB 比特软值）      → 训练/评估
                 └─ tb_bits（硬判＋解扰后的 TB 比特） → 部署（FAPI）
host：CRC 计算与判定 ＋ TB 打包 ＋ FAPI 封装
```

★ **输出边界（D18）**：★ **硬判与 TB 装配在模型内** ✓；★ **CRC 留在 host** ✓ ——
★ host 本来就会在 FAPI 边界出现 ✓ ⇒ ★ 不多一次穿越 ✓。

**与 Z 无关**：准循环结构 ⇒ 一层 = 基图每条边 × Z 条车道并行，**权重在 Z 维共享**。

## 5. 范围边界（**不做**）

| 不做 | 理由 |
|---|---|
| 用网络**替代**解码器（LLR 进、比特出）| 那是"更好的解码器"，不是 depth4 |
| Transformer 全码块 | O(n²)，26 112 bit 不可行 |
| 每迭代一次稠密前向 | 慢 6.5–76× |
| **"提前放弃"** | 实测：丢 1.1% 块换 2.1 µs |
| 基础模型/跨码族预训练 | 成本与实时性不适合 RAN |
