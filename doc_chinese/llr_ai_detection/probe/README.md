# 深度-3 的测量仪器（tracked）

> **要飞效用那一轮？先读 [`FLIGHT_RUNBOOK.md`](FLIGHT_RUNBOOK.md)** —— 前两次飞行各因一个配置错误白飞（`-b` 限速、
> MCS 被钉死），手册把这两个坑和"要贴回什么"固定下来了。

这些脚本是**测量仪器**，不是产品代码：它们决定"一个结论能不能被相信"。放在跟踪目录里，是因为
`work_tmp/` 被 gitignore（那里的语料/数据集太大），而仪器必须跨会话存活 —— 上一轮就有一批脚本只在
`work_tmp` 里，靠人工才知道怎么跑。

**数据与产物仍在 `doc_chinese/llr_ai_detection/work_tmp/`**（语料、数据集、模型 bundle、日志），所以脚本里
的 `W` 都指那里。运行前 `cd doc_chinese/llr_ai_detection/work_tmp`（或按脚本里的绝对路径调用）。

| 脚本 | 回答什么问题 |
|---|---|
| `check_matrix.sh` | 五旋钮 × 流水线的**配置矩阵**（21 行，合法/非法都跑真实二进制）。动过臂或 CLI 之后**必须**跑；2026-10-17 修过两处仪器缺陷：`mktemp` 模板（macOS 要求 X 在结尾）与过宽的覆盖行模式（把条件化契约的汇总行也算成一条覆盖） |
| `soak_timing.sh` | 一个进程跑 N 次接收，填满臂的 `[depth3-timing]` 环形缓冲（第 1 次与每 500 次打印）。**单条回放只有冷样本**，不能用来说稳态 |
| `ab_timing.py` | 两个二进制/两种设置**交错 ABBA** 计时；带 `--gap-ms` 调用间隔与模态标记（这台机器主机侧有 8× 的慢模态，只会抬高读数） |
| `scan_arch.sh` | 架构 → ANE 时延曲线：`train_depth3.py --probe-graph`（随机权重、只测时间）→ 编译 → 用真实臂计时，min-of-3 |
| `truncate_depth.py` | 把**已训练**模型按深度截断（权重不变，四个头接到第 k 块）并导出 |
| `refit_heads.py` | 冻结截断后的主干、**只重拟合四个头** —— 没有它，深度曲线量到的是"头的不适应"而不是能力 |
| `ber_by_snr.py` | 按 SNR 分箱的 uncoded BER（同一批样本）：看的是"地板"而不是被低 SNR 样本支配的总 BER |
| `capability_decode.sh` | 每个深度的**判决级**能力（真实捕获、真实链条） |
| `verify_compact.sh` | 压缩候选的五条预登记判据（判决等价 / head 3 / head 4 / criterion 1 / 时延与放置） |
| `verify_sinr_cal.sh` | 公布 SINR 标定的**留出**验证（拟合偶数位、验证奇数位） |
| `verify_xfer.sh` | 标定的**跨语料迁移**检验（另一采集会话） |
| `heads_vs_prescribed.py` | 目标的"已知真值"路线：在**指定** SNR 阶梯（0/6/12/18/24/30 dB）上量两个上报头（head 4 噪声误差、head 3 NMSE 与功率比）。当前树复现 12–30 dB 内 **+0.26…+1.22 dB**、head 3 **−24.8…−28.6 dB**，并显示 10 dB 以下两个头同时失效（定义域下限的依据）|
| `net_publication.py` | R6 的**精度半边**：同一接收上，`net` 公布的 RSRP/EPRE/SINR 与经典链公布值的差（分调制、中位与 p90）。这是"调度器真正读到的数"，不是估计器的内部量。当前树：16/64/256QAM 一致到 ~0.1 dB，QPSK 有 ~1.4 dB 的尾巴（§19.178） |
| `sinr_to_mcs.py` | 把公布 SINR 过一遍**调度器自己的** `map_snr_to_mcs_ul` 阈值表（从源码解析），给出经典链 / 未校准 / 校准三者的 MCS 分布与差值。**不含 OLLA**（它吸收恒定偏差），所以是**瞬时**上界；表在 23 dB 以上会饱和，验证要在有 MCS 余量的工作点做 |
| `selftest_flight_verdict.sh` | `flight_verdict.py` 的**回归测试**：在 r8abba 上必须复现 1.04/0.31/1.18 dB、A 11.20、B 9.79、−12.6%、FAIL。这个仪器先后被验证抓出**三个 bug**，每次都是这几个数之一在动 ⇒ 改完必须跑它（语料不在时**跳过**而不是失败）。除 r8 那一批外，它还带一份**合成夹具**（臂的真实行格式：`[depth3-measure]` / `[depth3-sinr]` / `[depth3-timing]`），所以**公布值列与时延解析**在历史日志早于仪器的情况下也有回归覆盖 —— 共 10 项 |
| `selftest_end_to_end.sh` | **黄金测试**：造两批合成腿（接收机对照 + 四臂），每条臂命中处置表的一个分支，断言输出的**确切措辞**（A/C 均值、"AI arm is BETTER by 18.0%"、"NO MEASURABLE DIFFERENCE"、D 的含义）。写它时抓到**我自己的期望值**算错（19.8% vs 18.0%）—— 工具对、手算错，这正是它存在的理由。失败时把两次运行的输出留在 `work_tmp/tmp/e2e/` |
| `fly_utility_abba.sh` | 一条命令跑**三臂镜像飞行**（a=AI 未校准 / b=AI 校准 / c=经典链，顺序 `a b c c b a`）在**投递形态**配置上。★ 它有一条关键守卫：**配置若仍钉着 `min/max_ue_mcs` 就拒绝开飞** —— 钉住 MCS 时公布 SINR 没有下游，标定的效用恒为零，飞了也证明不了任何事（§19.176）。已用两种配置验过守卫 |
| `flight_verdict.py` | 把一次飞行的腿目录 + 操作者贴回的 iperf3 变成**判据裁决**：每腿经典 SNR（可比性依据）、**公布 SINR（`[depth3-sinr]`）**、退化、时延，以及 **B≥A / B≥C** 的预登记结论。**按时间戳排腿**（ABBA 顺序就是判据本身），已用 r8abba / r7abba 复算出与记录一致的数。`basis` 列说明该腿的可比性依据来自哪里：AI 腿是估计器的**前均衡** SNR（抽样），经典腿是它**公布**的**后均衡**值（全采样）—— 相邻腿依据不同时会标 `different basis`。`[depth3-*]` 的数字取**所有行的中位数**：池按线程各建一个臂，一条腿的日志里有多条序列，取最后一行只会读到一个臂 |

`work_tmp/probe/` 里仍有同样的工作副本；**以本目录为准**，改动请改这里再同步过去。
