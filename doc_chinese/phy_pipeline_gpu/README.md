# `phy_pipeline gpu`：IQ → LLR 一步到底

> **本目录是这条线的唯一入口。**
> 旧的 `doc_chinese/full_gpu_chain/` 记的是**模块级卸载（`cpu_gpu`）**时代的推理与腿脚本，
> 它的很多结论在那个口径下成立、在**本目标**下不成立。**不要从旧目录继承结论，只继承证据。**

---

## 0. 一句话

**目标早已写在代码里**（`include/ocudu/phy/phy_pipeline_mode.h`）：

> **`gpu` — 融合车道。整条 IQ → LLR 链跑在一条设备侧流水线里，只有两次 host↔device 数据穿越
> （IQ 上传、LLR 下载）。LDPC 不属于车道。**

**而所有空口腿一直跑的是 `cpu_gpu`**——它自己的定义是"**每个模块边界都保留自己的 host↔device 穿越**"。
⇒ **差距不在"拷贝"（那一层已经清零并保持），而在"每个模块边界的那次往返"。**

## 2. 三条纪律（本线专用）

1. **判据是"穿越次数"，不是微秒。** 目标是一个架构性质（几次穿越），延迟只是副产品。
   任何"这不值 X µs"的论证**在本线一律无效**。
2. **不引用旧目录的结论，只引用它的原始观测。** 本目录写作时已经吃过一次亏：
   旧文档说 `host sample assembly` "只在 gpu 模式判定"，而代码
   （`lib/phy/lower/processors/uplink/uplink_processor_impl.cpp:226`）明写
   *"Judged in every published mode"* —— **旧描述是过时的**。
3. **每一步都要能单独判对错**：要么逐字节相同、要么契约明确变化、要么 A/B 可分辨。
   做不到这三者之一的改动，先补判据再动手。
