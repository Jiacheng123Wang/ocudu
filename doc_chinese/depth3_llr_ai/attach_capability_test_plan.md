# attach 阶段能力测试（2026-11-05 提出，**离线代理测量已给出不利结果**）

> **一句话**：接入阶段（3 PRB 的 Msg3、15 字节的 SRB1）是窄带、低码率、时延敏感的信令，
> 而**离线代理测量显示 E4 在 ≤3 PRB 上比经典链差 30.7%** ⇒ **attach 能力必须单独立项测，不能沿用宽带结论** ✓

---

## 1. attach 为什么特殊

| 特征 | 后果 |
|---|---|
| ★ **3 PRB 的 Msg3**（每次接入的第一条上行）| 窄带 ⇒ 模型在训练分布之外（历史 PRB 下限曾是 **4**）|
| **15 字节的 SRB1**（RRC 信令）| 低码率、极小时延预算 |
| **紧密的请求/应答** | ★ 实测 2026-10-18：出问题的腿 **SRB1 被重传 2 841 次**，接入窗口 PUCCH format-1 检出 15.7%（经典腿 45.9%）|
| 接入失败 = 整条腿不可用 | ★★ **代价远大于任何吞吐指标** |

## 8. ★★★★★ 2026-11-05 23:20 **查明"GPU 慢态"的真正原因：**c128 系列根本进不了 ANE**，而 c32 系列都行**

**(a) ★★★ 先回答"默认是不是尽可能走 ANE"——**不是**

| 事实 | 代码位置 |
|---|---|
| 引擎默认是 ★ **`MLComputeUnitsAll`**（Core ML 自己挑，**且不回报挑了哪个**）| `ocudu_coreml_nn_engine.mm:414–432` |
| `cpu_ne`（CPU＋ANE，**排除 GPU**）**存在**，是最接近"强制 ANE"的档 | 同文件 `:443` |
| ★ 但接收机把 `cpu_gpu`/`cpu_ne`/`cpu` **一律拒绝并改回 `all`** | `pusch_depth3_receiver_impl.cpp:377–391`（旧版）|

**⇒ 所以"默认走 ANE"是**期望**而不是**实现**；那次飞行 `all` 落到 GPU 就是证据 ✓
**⇒ 已改（2026-11-05）：接收机默认改为 `cpu_ne`**，`cpu_gpu`/`cpu` 仍拒绝，`all` 保留给 A/B ✓
