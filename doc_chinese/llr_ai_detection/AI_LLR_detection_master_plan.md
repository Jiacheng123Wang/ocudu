# AI LLR Detection 工作流 — 详细规划

> **工作流名称**：`llr_ai_detection`
> **一句话**：把 PUSCH 接收链的"均衡 + 解映射"（实测中位 **667.4 µs**）换成一次神经前向，
> **直接输出加扰域 LLR**，交给现有 LDPC 译码器。
> **前身**：`metal_kernel_fusion`（已收官：融合清单穷尽，性能目标在吞吐/占用维度关闭）。
> 本工作流继承它的问题陈述——"一格 667 µs 里只有几十 µs 是算力"——并换一条完全不同的路去解决它。
>
> 版本：v1.1 ｜ 状态：**规划（待 P0 裁决）** ｜ 日期：2026-10-07
> 配套文档：`memo_01_repo_seams_and_llr_contract.md`（接缝与契约）、
> `memo_02_paper_2503.16594_reading.md`（参考论文）、`memo_03_literature_survey.md`（文献调研）、
> `memo_04_data_labels_and_operating_point.md`（数据与工作点实测）
>
> v1.1 变更：补入 **OCUDU dApp 平台上 neural-receiver→LLR 的实测前作**（§1.2 新增"内联 vs dApp"
> 路线选择；§4 G5 获得 500 µs 对标基线；R5 获得论文级的错配实验支撑）。

## 0. 定位：两个目标必须分开排序，否则一定会自欺

| | 目标 | 内容 | 状态 |
|---|---|---|---|
| **G-A** | **时延** | eqdem 段 667 µs → 一次 ANE 前向 + 同步开销，**CRC 不明显掉** | **第一目标**，可行性已有锚点（HELENA@ANE 141 µs） |
| **G-B** | **精度** | 在少导频 / 高阶调制区间**超过**经典 MMSE + LLR | **待证伪的第二目标**，由 P0 裁决 |

★ 为什么必须分开：`memo_04` 实测我们的工作点是 **10.7% 导频密度、15–25 dB、宽分配、SISO**，
而参考论文（DEFINED）报告 43.7% / 71.1% 收益的区间是**极少导频**。**"AI detector 能提高精度"
是一个假设，不是前提。** 如果把它和时延目标混在一起讲，P0 一旦显示精度空间很小，
整个工作流就会被误判为失败——而它其实可能仍然值钱（时延）。

### 明确不做

- 不做端到端（**不替换 LDPC 译码器**）。译码器保持经典，LLR 是链条的接口。
- 不重构导频/参考信号，不动下行，不动 CE（CE 线由 `ai_ce` 独立负责）。
- 不追求"超过经典"作为 P0 之前的目标。

## 1. 接口契约（先钉死，再写代码）

全部依据见 `memo_01_repo_seams_and_llr_contract.md`。这里只列**冻结项**：

| 项 | 冻结值 |
|---|---|
| 宿主接缝 | `channel_equalizer::submit_fused()`，谓词 `supports_fused_demapping(mod, nof_ports, nof_layers)`（`include/ocudu/phy/upper/equalization/channel_equalizer.h:188-221`） |
| 输入 | `ch_symbols`（rx RE）、`ch_estimates`（`ch_est_list`，含 `device_slice`）、`noise_var_estimates`（per rx port）、`mod`、shape |
| 输出 1 | `llrs`：int8，**加扰域**，RE-major（`llrs[re*Qm + b]`），由浮点 LLR 经 `log_likelihood_ratio::quantize()` 得到 |
| 输出 2 | `eq_noise_vars`：**必须写**——后均衡 SINR 是上报统计，融合路由不得停掉（同文件 `:204-208`） |
| 量化 | `LLR_MAX=120`；`±127` = 确定比特；`range_limit` 按调制取 **24 / 24 / 20 / 20**（BPSK、QPSK、16QAM、64QAM） |
| 解扰 | **保持经典**（模型输出加扰域 ⇒ `pusch_demodulator_impl.cpp:730` 的 `revert_scrambling` 原样保留） |
| 回退 | 谓词为 false（不支持的 shape / 模型缺失 / 非 ARM 平台）⇒ 经典路径；**透明回退，绝不静默出错** |
| 开关 | `config.pusch_channel_equalizer_backend == "ai"`（沿用 `upper_phy_factories.cpp:743-756` 的形状）；CLI 覆盖仅用于调试 |

### 1.1 契约测试（是单测，不是文档）

1. **ALL-OR-NOTHING**：谓词为真时调用方**不得**再 demap 该符号（构造一个会断言二次 demap 的假 demapper）。
2. **谓词是 shape 的属性**：同一 shape 下对任意数值输入，谓词结果恒定。
3. **`eq_noise_vars` 非空且合理**：与经典后均衡噪声方差在同一量级（逐 RE 相对误差统计）。
4. **量化边界**：±120 裁剪、±127 语义、`quantize` 的 mid-tread 步长。
5. **加扰域一致性**：把经典 demapper 的输出与模型输出放在**同一域**对拍（同为加扰域）。
6. **回退等价**：开关关闭时，与 HEAD 的经典路径 **bit-exact**（用 `ab_dumps.sh` 的 0 差异控制臂）。

### 1.2 ★ 路线选择：内联（I）还是 dApp（D）—— **默认走 I**

文献调研发现了一条**直接对位的前作**（`memo_03` §1）：OCUDU **dApp 平台**上已有
**neural-receiver → LLR** 的实现，并给出了实测记账：每槽**输入 1.47 MB / 输出最多 4.4 MB**、
**占用 ≤ 500 µs**；dApp/E3 接口本身的开销是 **0.29 µs P99.9（静默）/ 5.2 µs（在空口上）**。
即"接口贵不贵"这个问题已经被回答：**接口是微秒级，真正的代价是数据搬运**。

| 路线 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **I 内联（默认）** | AI detector 就是一个 `channel_equalizer` 后端，走 `submit_fused()` | 自行处理 GPU↔ANE 同步 | 可能打破"一次提交"结构（R6） |
| **D dApp** | 走 OCUDU dApp / E3 接口 | 每槽 **1.47 MB 进 / ≤4.4 MB 出**的搬运 | ★ **与融合 lane 的核心成就正面冲突** |

★ 为什么默认走 I：本仓库 `phy_pipeline_gpu` 的核心成就正是**零主机↔设备数据穿越**
（`phy_pipeline_crossings.h` 的整个设计目的就是这个计数）。在**统一内存架构**上走 dApp，
等于**主动把这笔穿越加回来**——这是一个需要论证、而不是可以默认接受的取舍。
⇒ 路线 D 保留为**对照臂**与"若内联做不到"的退路；若最终走 D，必须把 1.47/4.4 MB 的搬运
计入 G5 的时延，并与前作的 500 µs 占用**同口径对比**。

## 2. 模型设计：三个候选，按风险递增

任务重述：`f(网格切片, 信道估计, σ², 调制, DM-RS 掩码) → 逐 RE 浮点 LLR`

| 候选 | 形态 | 替换掉什么 | 风险 | 定位 |
|---|---|---|---|---|
| **A1 神经解映射器** | 输入 = **均衡后**符号 + 逐 RE σ²；小 CNN 输出 LLR | 只替换 `demodulate_soft`（几十 µs） | 最低 | **P2 的第一个原型**；时延收益小，但用于验证"损失/标度/量化"整条链路 |
| **A2 联合均衡 + 解映射** | 输入 = **原始 rx RE** + 信道估计（多端口）+ σ²；2D 卷积（时频局部性天然匹配）输出逐 RE LLR | 替换 **eqdem 整段（667 µs）** | 中 | **主线**。形态与 DeepRx / Sionna Neural Receiver 同类【见 memo 03】 |
| **A3 ICL / 判决反馈 Transformer** | DM-RS 作 in-context 示例 + 判决反馈（论文形态，0.42 M / 8 层） | 同上 | **高**：注意力 O(N²) 与 DF 串行性直接和实时预算冲突（memo 02 §4.3、§7.5） | **研究支线**，不作为主线 |

### 2.1 输出参数化：直接输出 LLR

论文的输出头是"对星座点分类"，再边缘化得到 LLR（memo 02 §4.1）。我们**直接输出 LLR**：

- 省掉推理时的 log-sum-exp 边缘化；
- 损失可以直接定义在 LLR 域（BCE / 回归 / KL），与译码器接口同域；
- 星座分类头唯一的优势是天然归一化（概率），但这一点可以用**标度校准**（§3.3）替代。

### 2.2 复数与精度

- I/Q 两路实数拼接是标准做法。
- 信道估计在链上是 `cbf16_t`（bf16）。**bf16 → fp16 的精度损失必须在 P2 度量**，不能假设无影响
  （本仓库已经有过"同一份源码在不同编译上下文产生不同 bf16 比特"的教训，见 `metal_kernel_fusion` §2.27）。

### 2.3 尺寸与时延预算

**唯一锚点**：HELENA 116k 参数 @ ANE，输入 `(1,612,14,2)`，p50 **141 µs** / p99 208 µs。
我们的输入更大（51 PRB = 612 子载波 × 14 符号已同量级），输出是逐 RE 的 Qm 个 LLR。
⇒ **参数量与 FLOPs 上限必须实测反推**，禁止外推。P4 的第一件事是"空模型测时延"（把权重换成随机值，
只测前向时间随宽度/层数的曲线）。

### 2.4 模型形态的硬约束（来自接缝）

- `submit_fused` 是**单符号/单组**调用（`pusch_demodulator_impl.cpp:601`），模型的 batch 维度
  应当映射到"符号组"，而不是"整个 slot"，否则会与调用方的分页/步长约定冲突。
- 输出必须写到调用方给的 `llrs` 视图（RE-major、每符号等步长），**不能假设连续内存**。

## 3. 训练与损失

### 3.1 标签

| 路线 | 来源 | 用途 | 规模 |
|---|---|---|---|
| **1（主）** | CRC-OK TB → LDPC encode → rate match → scramble → modulate ⇒ **真实发送比特** | 主监督 | ≈ **17.7 万次接收**（134,181 + 42,853） |
| 2（辅） | 经典链 LLR（`_llr.bin` / `ul_chain_replay` 重生成） | 热身、消融 | 任意（可离线批量生成） |

细节与陷阱（解扰域、`n_rapid`、msgA 排除）见 `memo_04` §3。

### 3.2 损失（按优先级）

1. **逐比特 BCE**（对真值比特）——主损失。允许模型超过经典 demapper（无蒸馏天花板）。
2. **LLR 回归 / KL**（对经典 LLR）——预训练热身 + 消融对照。
3. **码字级 / 译码器感知**：仓库里有 Metal LDPC 译码器，可以做一个"以 CRC 通过为信号"的微调阶段。
   **先做离线批处理版本，不做 RL。**

### 3.3 标度校准（独立步骤，不是训练细节）

经典 demapper 的 LLR 与噪声方差成反比（`demod_BPSK_symbol`：`2√2·(Re+Im)/σ²`）。
模型的浮点输出**整体标度**必须与 `range_limit` 匹配，否则量化后要么大面积饱和、要么全部挤在 0 附近，
两种都会让 LDPC 直接崩掉。

- 做法：训练后单独拟合一个标度/温度参数，最大化量化后 LLR 与真值比特的互信息；
- **验收**：量化**前**与量化**后**的 CRC 差异 ≤ 预登记阈值。

### 3.4 数据划分（★ 曾吃过大亏的地方）

**必须按采集时段/会话划分，禁止随机划分。** 同一信道的相邻 slot 若同时出现在训练集与测试集，
会产生严重泄漏，指标会好看而部署会崩——这正是 AI CE "训练/部署错配"那一类错误的近亲。
划分脚本要**检查并打印**：训练/测试集的 slot 范围不重叠、`rnti` 不重叠、`n_prb`/`mod`/SNR 分布对照表。

### 3.5 增强

只能在**物理上成立**的维度上做增强：噪声重采样（人工加噪到目标 SNR）、相位/定时扰动、
功率缩放。**禁止**做会改变标签的增强（例如随机擦除数据 RE 而不更新标签）。

## 4. 阶段与门禁（沿用 AI CE 的 G 门禁范式：门禁是**预先商定**的判据，未记录测量不得前进）

| 阶段 | 内容 | 门禁 | 预登记判据 |
|---|---|---|---|
| **P0** | **值不值得做**：经典链的导频/SNR 扫描 + genie 上界 | **G0** | 给出"检测环节可改善空间"的**量化上界**（memo 04 §4 的 P0-a/b/c）。**若上界很小 ⇒ 工作流只保留 G-A（时延）目标，或终止** |
| **P1** | 离线数据管线：grid + TB → 训练集（划分、增强、统计、复现脚本） | G1 | 数据集可一键复现；泄漏检查通过；**经典链在同一测试集上的 SER/BLER 已记录**（否则后面没有可比基线） |
| **P2** | A1 神经解映射器：离线训练 | G2 | 留出集上 BER/互信息 ≥ 经典（或差距 ≤ 预登记阈值）；标度校准后 CRC 不掉 |
| **P3** | A2 联合模型：离线训练，覆盖 16/64/256QAM | G3 | 同 G2，且**逐调制**分别达标；给出参数量/FLOPs 与 ANE 时延外推 |
| **P4** | **接链**：实现 `channel_equalizer` 后端 + 谓词 + 回退 + 契约测试 + crossings 声明 | G4 | §1.1 六项单测全过；开关关闭时与经典 **bit-exact**；开关打开时 CRC ≥ 参考 |
| **P5** | 实时性：ANE 端到端时延 + **同步开销** | G5 | p99 时延 ≤ 目标。**两个对标基线**：① 现网 eqdem 的 **667.4 µs**（mkf033 中位）；② 文献里 neural-receiver→LLR dApp 的 **≤500 µs 槽占用**（`memo_03` §1）。★ **必须包含 GPU→ANE 的等待与 ANE→LDPC 的可见性开销**，不得只报前向时间 |
| **P6** | OTA 实测：真实采集上的 CRC/BLER A/B | G6 | 统计门通过（同批采集、同一译码器、同一 LDPC 配置） |

★ 门禁纪律（继承自 `metal_kernel_fusion`，都是付过学费的）：

1. **判据在飞之前写死**；事后改判据等于没有判据。
2. **计数器必须能证明开关真的生效**（"开关没生效 ≡ 没有效果"在本仓库出现过三次）。
3. **每个数字都要能追溯到一次 leg / 一个 commit**；引用别人的数字要标来源等级。
4. **禁止用两个测量相减做归因**（本仓库为此错过两次）。

## 5. 风险清单（每条给早期信号与退路）

| # | 风险 | 早期信号 | 退路 |
|---|---|---|---|
| **R1** | **精度收益不存在**（工作点在经典链已近最优的区间） | G0 的可改善空间上界很小 | 工作流收缩到 G-A（时延）；或终止并如实记录 |
| **R2** | 模型太大，**ANE 跑不动** | P2 的宽度/层数-时延曲线超预算 | 降到 A1/A2 卷积形态，砍层/宽度；或让 ANE 只处理部分符号 |
| **R3** | **判决反馈的串行性**与实时冲突 | DF 轮数 × 单轮时延 > slot 预算 | 无 DF 的一轮并行检测（A2 本身就没有 DF） |
| **R4** | **LLR 标度/量化不匹配**：离线指标好、CRC 崩 | 量化前后 CRC 差异大 | §3.3 标度校准；逐调制重标定 `range_limit` |
| **R5** | **训练/部署错配**（AI CE 的老坑） | 仿真好、OTA 差 | **"把适配写进输入格式"**——DEFINED 已显式验证 Rayleigh(NLOS) 训练 → Rician(LOS) 测试的错配场景（`memo_02` §3.1）；辅以 OTA 微调 |
| **R6** | **打破融合 lane 的"一次提交"结构** | crossings 计数上升、`gap` 变大 | 显式声明新同步点；或改走 dApp 路线 D——但那时要把 **1.47/4.4 MB 的每槽搬运**计入 G5（§1.2） |
| **R7** | 语料不足（17.7 万次接收 vs 0.4 M 参数量级模型） | 训练/验证曲线分离 | 仿真为主 + OTA 微调；先训小模型 |
| **R8** | 与 CUDA/NVIDIA 路线相比无优势 | 竞品分析 | 如实记录（仓库已有 `metal_vs_cuda_architecture.md` 的方法论） |

★ R6 值得单列一段：当前融合 lane 的核心性质是**一次提交 + 设备排队**（`metal_kernel_fusion` §2.33）。
把 eqdem 移到 ANE 会引入 **GPU → ANE** 与 **ANE → LDPC** 两个新的同步点。
**这两个等待必须被测量并计入 G5**，否则就是"把 667 µs 的空白换成了另一个没被测量的空白"。

## 7. 与 `metal_kernel_fusion` 的关系

| | 复用 | 差异 |
|---|---|---|
| 交叉计数契约 | `phy_pipeline_crossings` / `phy_pipeline_grid_ready` 的纪律直接用 | AI 路径**必须新增声明**（GPU↔ANE）；若走 dApp 路线则**主动增加**每槽 1.47/4.4 MB 搬运（§1.2） |
| 验收方式 | 离线重放、leg 协议、Linux 复验流程 | **门禁从"0 差异"变成"统计不劣"**（AI 不可能 bit-exact） |
| 问题陈述 | eqdem 667 µs、一次提交 + 设备排队 | 本工作流是它的**续集**：不动 GPU 内核，换执行引擎 |

★ 一句话交接：**上一个工作流证明了"在这条链上，时间不是被算力吃掉的"；
本工作流要证明的是"把这段计算搬到另一个引擎上，能否真的把时间拿回来"。**
如果搬到 ANE 只是把 667 µs 的空白换成另一个空白，那么结论应当如实记录为——
**瓶颈不在计算引擎，而在链路的时序结构**（slot pacing / 设备排队），这本身仍是有价值的结论。

## 8. 本规划中尚未确认的部分（诚实清单）

1. **G-B（精度收益）是否存在** —— 由 P0 裁决，规划不预设结论。
2. A2 的具体网络形态与参数量 —— 待 P0 与 `memo_03` 文献调研共同确定。
3. ANE 上大模型的真实时延 —— 现有锚点只有 116k 参数；更大模型的曲线必须实测。
